# 3.2 Text field

A Text field is the complete form field for typed data: a **Label** on top, the **Text control** in the middle and a **Help text** underneath. This page holds three field families: the single-line `Text field` with its thirteen special types, the multi-line `Textarea field`, and the `Code field` for verification codes.

Text fields are used for user-entered data in forms and dialogs. Use a Select (3.5) when the user picks from a known list, a Choice field (3.3) for yes/no and one-of-few choices, and a Rich text editor (4.1) when the user needs formatting.

Product note: on mobile web, the value text inside the control must be at least 16 so the browser does not zoom into the field on focus. This is set once in the Text control (2.10) and every field inherits it.

# 4. Text field

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `md` |
| `Type` | variant | `default, leading-text, leading-dropdown, trailing-dropdown, trailing-button, password, payment, date-time, tags-inner, tags-outer, counter-horizontal, counter-vertical, file-upload` | `default` |
| `Status` | variant | `none, invalid` | `none` |
| `Filled` | variant | `false, true` | `false` |
| `State` | variant | `rest, focus, disabled` | `rest` |
| `Show label` | boolean | — | `true` |
| `Show hint` | boolean | — | `true` |
| `Show time` | boolean | — | `false` (only `Type=date-time`) |

Variants: `Size` 3 × `Type` 13 × (`Filled` 2 × `State` 3 × `Status` 2, minus the 2 `State=disabled, Status=invalid` combinations) = 3 × 13 × 10 = **390**.

`Filled=false` shows the placeholder; `Filled=true` shows a value. `Status=invalid` is the validation state: it changes the control border and the Help text to danger and never creates a separate anatomy. Hover is shown on the Text control page (2.10); the field matrix shows rest, focus and disabled.

## Anatomy

```text
Text field
layout: Vertical, gap space/sm, width `size/width/xxs` = 320 in the set (Fill in layouts), Hug height

├─ Label                         instance 2.11, Fill width                 Show label
├─ Control                       Horizontal, gap −border/width/default, Fill width, Hug height
│  ├─ Leading addon              .Main/Text field addon, Placement=left    type-driven
│  ├─ Text control               instance 2.10 (or .Main/Text field tag box for tags-inner), Fill
│  └─ Trailing addon             .Main/Text field addon, Placement=right   type-driven
├─ Tags                          Horizontal wrap, gap space/sm, Fill       Type=tags-outer
│  └─ Tag × n                    instance 2.5
└─ Help text                     instance 2.12, Fill width                 Show hint
```

Flexible vs fixed:
- `Text control` fills the remaining width of `Control`; addons hug their content.
- `Label`, `Help text` and `Tags` fill the field width; long hints wrap under the control.
- The field never sets its own height; it grows with wrapped hints and tag rows.

## What each Type changes

Type is never cosmetic. Each value changes one or both slots around the value:

| Type | Leading | Inside the Text control | Trailing |
| --- | --- | --- | --- |
| `default` | — | optional leading icon (`mail` in the hero), optional help icon (`Show help icon`) | — |
| `leading-text` | — | `Show prefix` on: static prefix "https://" inside the box, then the value | — |
| `leading-dropdown` | addon `Type=dropdown` ("US" + chevron) | value ("+1 555 0100") | — |
| `trailing-dropdown` | — | value ("1,000.00") | addon `Type=dropdown` ("USD" + chevron) |
| `trailing-button` | — | value | addon `Type=button` with a Button (2.1) "Copy" |
| `password` | — | value shown as dots; `Show trailing icon` on with the `eye` icon | — |
| `payment` | — | `Leading icon` swapped to a card mark from 1.8 (24 × 16); value "1234 1234 1234 1234" | — |
| `date-time` | — | leading `calendar` icon; date value | addon `Type=dropdown` with the time ("09:00") when `Show time` is on |
| `tags-inner` | — | `.Main/Text field tag box`: Tags then the typing text, wrapping | — |
| `tags-outer` | — | value | — ; Tags sit in the `Tags` row under the control |
| `counter-horizontal` | addon `Type=stepper` with a minus icon | value, centered | addon `Type=stepper` with a plus icon |
| `counter-vertical` | — | value | addon `Type=stepper-vertical`: decrease (−) and increase (+) side by side, divider between |
| `file-upload` | addon `Type=button` with a Button "Choose file" | file name, or placeholder "No file chosen" | — |

## Joined edges

Addons and the control sit edge to edge as one shape:
- `Control` has a negative gap equal to `border/width/default` (−1), so the addon's border and the control's border overlap into one line.
- The outer corners keep `radius/control`; the joined corners are square. The addon draws radius only on its outer side (set by `Placement`); the Text control instance has its joined-side corners overridden to 0.
- On `State=focus`, the Text control is brought in front of the addon so its focus ring is not covered.

## Sizes and measurements

The field stack uses the same values at every size; heights and paddings come from the Parts.

| Size | Control height | Label | Help text | Stack gap | Addon padding x | Addon Button |
| --- | --- | --- | --- | --- | --- | --- |
| `sm` | `size/control/sm` = 36 | `Size=sm` | `Size=sm` | `space/sm` = 6 | `space/lg` = 12 | `Size=sm` |
| `md` | `size/control/md` = 40 | `Size=md` | `Size=md` | `space/sm` = 6 | `space/lg` = 12 | `Size=md` |
| `lg` | `size/control/lg` = 44 | `Size=md` | `Size=md` | `space/sm` = 6 | `space/xl` = 16 | `Size=lg` |

Default width of every set in the matrix: `size/width/xxs` = 320. In product layouts the field is set to Fill.

## States

| Field variant | Label | Text control | Addons | Help text |
| --- | --- | --- | --- | --- |
| `Filled=false, State=rest` | rest | placeholder, rest | rest | `Status=none` hint |
| `Filled=true, State=rest` | rest | value, rest | rest | hint |
| `State=focus` | rest | focus ring and focus border | rest; Button addon unchanged | hint |
| `State=disabled` | rest (the label stays readable) | disabled | disabled: icons and text `color/text/disabled`, no hover | hint |
| `Status=invalid` | rest | invalid border (and invalid focus ring when focused) | border joins in `color/border/danger` | `Status=invalid`, error copy |

## Anatomy

```text
Textarea field
layout: Vertical, gap space/sm, width `size/width/xxs` = 320 in the set, Hug height

├─ Label                         instance 2.11                    Show label
├─ Text control                  instance 2.10, Type=multi-line, Fill width
```

- Text starts at the **top left** of the control. Never center textarea content vertically.

- The resize handle sits in the bottom trailing corner, inside the control's padding; it belongs to the multi-line Text control.

```text
├─ Label                         instance 2.11                    Show label
```

# 7. Private parts

## .Main/Text field addon

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `md` |
| `Type` | variant | `dropdown, button, stepper, stepper-vertical` | `dropdown` |
| `Placement` | variant | `left, right` | `left` |
| `State` | variant | `rest, hover, disabled` | `rest` |
| `Text` | text | — | `US` |
| `Icon` | instance swap | icons | `Icon/arrows/chevron-down` |

```text
.Main/Text field addon
layout: Horizontal, align Center, Hug width, height size/control/{Size}
padding-x: space/lg (lg: space/xl); stroke border/width/default; radius on the outer side only

├─ Text                          type/body/{sm|md}/regular        dropdown
├─ Icon                          size/icon/md                     dropdown (chevron), stepper (minus/plus)
├─ Button                        instance 2.1, Emphasis=secondary  button (fills the addon; the addon draws no padding)
└─ Steps                         Horizontal: minus cell, divider (border/width/default, color/border/default), plus cell; each cell at least 24 × 24   stepper-vertical
```

- Every step is a target of at least 24 × 24 (WCAG 2.2 target size, 2.5.8). Two stacked half-height chevrons in a 36–44 control are about 16 high and fail, so `stepper-vertical` places − and + side by side. Stack them only in a control at least 48 high, so each step gets 24. The value keeps the name `stepper-vertical` until the next major version (`ROADMAP.md` §2).

- `dropdown` and the steppers are interactive: surface `color/fill/none`, hover `color/fill/neutral/subtle/hover`.
- A static prefix is not an addon: it is the Text control's own `Prefix`, inside the box.
- `button` holds a real Button instance. It is never text styled to look clickable.

```text
.Main/Text field tag box
layout: Horizontal wrap, gap space/sm, Fill width, Hug height (min size/control/{Size})
padding: same as the Text control of the same Size; radius/control; stroke border/width/default

├─ Tag × n                       instance 2.5, Size sm (md and lg fields) or xs (sm field)
```

It exists because an instance of the Text control cannot hold Tags inside it. It binds **the same fill, border, focus and status tokens as the Text control**, so a change to the control's look reaches it too. Tags wrap to new lines and the box grows in height; it never scrolls sideways.

# 8. Matrix layout

`Text field` in `· Component`:
- one block per `Type`, in the order of the property table, each with a `Doc/Axis label` title;
- inside each block: columns `Filled` → `State` (placeholder, filled, focus, disabled), rows `Size` → `Status`.

`Textarea field`: blocks by `Type`; columns `Filled` → `State`; rows `Size` → `Status`.

`Code field`: columns `Type`, rows `Size`.

`.Main`: addon (columns `State`; rows `Type` → `Placement` → `Size`), tag box (columns `State`; rows `Type` → `Status` → `Size`), code cell (columns `Filled` → `State`; rows `Size` → `Status`).

Do not replace the 390-variant `Text field` set with a showcase of a few fields.

# 10. Guidelines

Topics in `3.2 Text field · Guidelines`, in order, each with a visual built from real instances:

1. **When to use.** Text field, Select (3.5), Choice field (3.3) and Rich text editor (4.1) side by side, each with a one-line reason.
2. **Label → control → hint.** A field with callouts on the three parts and the `space/sm` gaps measured. Caption: "Every field is the same three rows; only the control changes."
3. **Status is not a State.** A grid: rest / focus / disabled across, none / invalid down. Caption: "Invalid describes the value; focus describes where the user is. A field can be both."
4. **Types change the slots.** The type gallery from `· Anatomy`, reduced to the five most used types, with a callout on the slot each changes.
5. **Joined edges.** A leading-dropdown field and a trailing-button field zoomed in, with callouts on the single shared border line and the square inner corners.
6. **Tags grow the field.** A tags-inner field with two tags and with seven tags (wrapped to two lines). Caption: "Tags wrap; the field grows down, never sideways."
7. **Code fields.** 4-digit and 6-digit fields; callout on the separator. Caption: "Group long codes so they are easy to read back."
8. **Mobile text size.** A field on a phone frame with the value at 16 and a callout: "16 or larger stops the browser zooming in on focus."
9. **Content.**
   - Labels name the data ("Email address"); hints say what a valid value looks like; placeholders show an example, never the instructions.
   - Error messages say how to fix it: "Enter a date after 1 January 2026."
   - Keep prefixes and suffixes short ("https://", "USD", "kg").
10. **Accessibility.**
    - The Label is the control's name and the Help text its description.
    - Addon dropdowns and steppers are their own focusable controls with names ("Country code", "Increase quantity"); each stepper is at least 24 × 24.
    - In `tags-inner` and `tags-outer`, the typing text is labeled by the field Label (or has its own accessible name).
    - In `file-upload`, the file input behind "Choose file" has an accessible name (the field Label), even when it is visually hidden.
    - A password reveal icon is a button with a name that changes ("Show password" / "Hide password").
    - Code fields accept paste of the whole code and move focus to the next cell as each digit is typed.
    - Invalid state is shown by border color **and** the error text.
11. **Do / don't** (`Doc/Do-dont` pairs):
    - Do keep the Label visible. Don't use the placeholder as the label.
    - Do use a Button addon for actions. Don't style addon text as a link.
    - Do let tags wrap. Don't let a tags field scroll sideways.
    - Do keep code cells large. Don't shrink cells to fit six digits into a narrow column.
    - Do top-align textarea text. Don't center it vertically.
12. **Maintenance.** Change the box in Text control (2.10), label type in Label (2.11), hint and error style in Help text (2.12); change addons, the tag box and code cells in `.Main` here.

# 11. QA

Fail QA when:
- Label, control and hint are flattened into unrelated layers instead of Label, Text control and Help text instances;
- a special `Type` is shown only by different placeholder text instead of its slot content;
- the Text control does not fill while addons hug;
- two border lines show where an addon meets the control, or inner corners are rounded;
- a trailing button is text instead of a Button instance;
- textarea text is vertically centered;
- code cells are duplicated frames instead of `.Main/Code field cell` instances, or the 6-digit field has no grouping;
- the tag box uses different tokens from the Text control;
- `Status=invalid` is built as a separate set or a `Destructive` property;
- the 390-variant `Text field` matrix is replaced by a small showcase;
- a stepper is smaller than 24 × 24, or steppers are stacked in a control less than 48 high;
- the tags typing text or the file-upload input has no accessible name.
