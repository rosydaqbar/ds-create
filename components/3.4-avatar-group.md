# 3.4 Avatar group

Avatar groups show several people at once: an **Avatar group** overlaps avatars into a compact stack with an optional "+N" count and an add button; an **Avatar label** puts one avatar next to a name and a supporting line, such as an email or role.

Use an Avatar group to show who is on a project, document or call without listing names. Use an Avatar label wherever a person is named in a list, menu, table cell or header. A single avatar on its own is the Avatar Part (2.6), which also holds the avatar image, placeholder and colour documentation.

# 4. Avatar group

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `xs, sm, md` | `sm` |
| `Count` | text | — | `+5` |
| `Show count` | boolean | — | `true` |
| `Show add button` | boolean | — | `true` |

Variants: **3**. The avatars inside are exposed nested instances so designers swap the people without detaching.

## Anatomy

```text
Avatar group
layout: Horizontal, align Center, gap space/md, Hug

├─ Avatars                       Horizontal, gap = avatar-group/overlap/{Size} (negative), Hug
│  ├─ Avatar                     instance 2.6, Show ring on      (first, on top)
│  ├─ Avatar × 4
│  └─ Count                      instance 2.6, Type=initials, Initials "+5", Show ring on   Show count
└─ Add button                    .Main/Avatar group add button              Show add button
```

- Avatars overlap through a **negative gap**, never through absolute positioning, so adding or removing a person keeps the stack even.
- Earlier avatars sit on top of later ones (Auto Layout "first on top"), so the first person is fully visible.
- Each avatar has `Show ring` on: a ring in `color/surface/base`, which separates the overlapping circles on any background.
- The count uses the same Avatar footprint as its neighbours, so it lines up with the stack.
- The add button sits **outside** the overlapping stack with a normal positive gap; it never overlaps an avatar.

## Sizes and measurements

| Size | Avatar | Overlap | Count style | Add button | Gap to add button |
| --- | --- | --- | --- | --- | --- |
| `xs` | `size/avatar/xs` = 24 | `avatar-group/overlap/xs` = −4 | from Avatar `xs` | 24 | `space/md` = 8 |
| `sm` | `size/avatar/sm` = 32 | `avatar-group/overlap/sm` = −8 | from Avatar `sm` | 32 | `space/md` = 8 |
| `md` | `size/avatar/md` = 40 | `avatar-group/overlap/md` = −12 | from Avatar `md` | 40 | `space/md` = 8 |

Default content: five avatars, count "+5", add button on. Show at most five avatars; beyond that, the count takes over.

| `Text` | text | — | `Olivia Rhye` |
| `Supporting text` | text | — | `olivia@example.com` |
| `Show supporting text` | boolean | — | `true` |

Variants: **3**.

## Anatomy

```text
Avatar label
layout: Horizontal, align Center, gap per Size, Hug width (Fill in layouts)

├─ Avatar                        instance 2.6, Fixed
└─ Text and supporting text      Vertical, gap 0, Fill
   ├─ Text                       semibold, truncates with an ellipsis
   └─ Supporting text            regular, truncates          Show supporting text
```

- The avatar never shrinks; the text stack fills and truncates when space runs out.
- No spacer between Text and Supporting text: the line heights give the rhythm.

# 8. Guidelines

Topics in `3.4 Avatar group · Guidelines`, in order, each with a visual built from real instances:

1. **Group or list.** An Avatar group next to a list of Avatar labels showing the same five people. Caption: "Use a group when who matters less than how many; list names when people need to be identified."
2. **Overlap.** A zoomed group with the negative gap measured and a callout on the ring. Do: overlap with Auto Layout. Don't: positive gaps between avatars, or avatars dragged into place.
3. **The count.** Groups of 3, 5 and 12 people. Caption: "Show up to five; the count shows the rest and keeps the avatar footprint."
4. **The add button.** Do: add button after the stack with a normal gap. Don't: add button overlapped into the stack.
5. **Avatar label content.** Text is the person's name; supporting text is the most useful second fact for the context (email in admin lists, role in team pages). Long names truncate; the avatar never shrinks.
6. **Accessibility.**
   - A group has an accessible name that includes the total ("12 people: Olivia Rhye, Phoenix Baker and 10 more").
   - The count opens or links to the full list; hovering shows a Tooltip (2.13) with the hidden names.
   - The add button is a button named "Add people" and shows a Tooltip with the same text.
   - In an Avatar label, the name is text, so the avatar image is decorative there.
7. **Do / don't** (`Doc/Do-dont` pairs):
   - Do keep every avatar in a group the same size. Don't mix sizes in one stack.
   - Do use the ring. Don't let overlapping images merge.
   - Do truncate long names. Don't shrink the avatar to fit a long name.
8. **Maintenance.** Avatar images, placeholders and colours are changed on the Avatar page (2.6) and reach every group and label. Overlap and spacing live here.

# 9. QA

Fail QA when:
- avatars in a group use positive gaps or absolute positions instead of a negative Auto Layout gap;
- the count has a different footprint from the avatars;
- the add button sits inside the overlapping stack, or is a hand-drawn circle instead of `.Main/Avatar group add button`;
- avatars are drawn shapes instead of Avatar (2.6) instances;
- an Avatar label avatar shrinks when the text is long;
- overlapping avatars have no ring;
- the matrix shows only one size.
