# 3.1 Button group

A Button group joins related actions into one connected control: a small toolbar ("Bold / Italic / Underline"), a split action, or a compact view switcher ("Day / Week / Month"). Items touch each other, share one outer border and one outer radius, and each item keeps its own states.

Use it when the actions belong together and are used side by side. Use separate Buttons (2.1) when the actions are independent, tabs when switching changes a whole page section with its own content, and Radios (2.8) inside a Choice field (3.3) when a form needs one choice saved on submit.

# 4. .Main/Button group item

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md` | `md` |
| `Icon only` | variant | `false, true` | `false` |
| `Selected` | variant | `false, true` | `false` |
| `State` | variant | `rest, hover, focus, disabled` | `rest` |
| `Label` | text | — | `Button` |
| `Show leading icon` | boolean | — | `false` |
| `Leading icon` | instance swap | icons | `Icon/general/placeholder` |
| `Show dot` | boolean | — | `false` |
| `Show divider` | boolean | — | `true` |

Variants: `Size` 2 × `Icon only` 2 × `Selected` 2 × `State` 4 = **32**.

`Show leading icon` and `Show dot` are not used together; the dot replaces the icon when a segment needs a status marker ("Active").

## Anatomy

```text
.Main/Button group item
layout: Horizontal, align Center, Hug × Fixed height
padding: button-group/item/padding-y/{Size}, button-group/item/padding-x/{Size}
gap: space/sm

├─ Divider              1px line on the leading edge, absolute, full height   Show divider
├─ Dot                  size/indicator/sm, radius/full                        Show dot
├─ Leading icon         instance, size/icon/md                                Show leading icon
├─ Text padding         Horizontal, padding-x space/optical, Hug                  hidden when Icon only=true
│  └─ Label             type/body/sm/semibold
└─ Icon                 instance, size/icon/md                                Icon only=true
```

- `Text padding` is the same optical wrapper as Button (2.1): it adds `space/optical` (2) on both sides of the label so the text looks centered next to an icon whose glyph has built-in padding.
- `Divider` is an absolutely positioned line (`border/width/default`, `color/border/default`) on the leading edge. It is the only border between two items, so borders never double.

## Sizes and measurements

| Size | Height | Padding x | Padding y | Gap | Icon | Text style |
| --- | --- | --- | --- | --- | --- | --- |
| `sm` | `size/control/sm` = 36 | `space/lg` = 12 | `space/md` = 8 | `space/sm` = 6 | `size/icon/md` = 20 | `type/body/sm/semibold` |
| `md` | `size/control/md` = 40 | `space/xl` = 16 | `space/md` = 8 | `space/sm` = 6 | `size/icon/md` = 20 | `type/body/sm/semibold` |

- Height is fixed to the size token; content is centered vertically inside it.
- With `Icon only=true` the width is fixed to the same size token (36 or 40), so the segment is square and the icon is centered.
- The padding values are the component tokens `button-group/item/padding-x/{Size}` and `button-group/item/padding-y/{Size}`, which alias the space tokens above.

## States

| State | Item fill | Label and icon | Notes |
| --- | --- | --- | --- |
| `rest` | `color/fill/none` | `color/text/secondary`, `color/icon/secondary` | |
| `hover` | `color/fill/neutral/subtle/hover` | `color/text/primary`, `color/icon/primary` | |
| `focus` | rest fill | rest colors | `focus/default` effect drawn inside the item so the neighbor does not cover it |
| `disabled` | `color/fill/none` | `color/text/disabled`, `color/icon/disabled` | no hover |
| `Selected=true` | `color/fill/neutral/subtle/selected` | `color/text/primary`, `color/icon/primary` | combines with every `State` |

`Selected` and `State=focus` are separate: a selected segment can be focused or not, and focus never changes which segment is selected.

# 5. Button group

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md` | `md` |
| `Icon only` | variant | `false, true` | `false` |

Variants: **4**. Each item inside is an exposed nested instance, so designers set `Label`, `Selected`, `State` and the icons per segment without detaching.

## Anatomy

```text
Button group
layout: Horizontal, gap 0, Hug × Hug
stroke: border/width/default, color/border/default (outer border, inside)
radius: radius/control
clip content: on

├─ .Main/Button group item     Show divider = false   (first)
├─ .Main/Button group item     Show divider = true
├─ .Main/Button group item     Show divider = true
└─ …
```

Default content: three items, the first `Selected=true`.

## Connected edges

- The **group** owns the outer border and the outer radius. Clipping rounds only the outside corners of the first and last items; inner corners stay square.
- Items have **no border of their own**. The `Divider` on each item's leading edge is the single line between neighbors. The first item turns it off.
- The group has no shadow by default. When secondary Buttons (2.1) in this system carry a shadow, the group uses the same effect style so a group and a Button side by side match.
- A focused item draws its focus ring inside its own bounds so it is not clipped by the group or covered by the next item.

# 8. Guidelines

Topics in `3.1 Button group · Guidelines`, in order, each with a visual built from real instances:

1. **When to use.** Side-by-side cards: Button group (view switcher), separate Buttons (unrelated actions in a dialog footer), tabs (page sections). One-line reason under each.
2. **Connected edges.** A zoomed three-item group with callouts on the outer border, the single divider between items, the rounded outer corners and the square inner corners.
3. **Selected vs focus.** Four items in a row: unselected, selected, focused, selected + focused. Caption: "Selection is a fill; focus is a ring. They never replace each other."
4. **Text, icon and icon-only.** One group of each form, all at `md`.
5. **Content.** Labels are one or two words, same grammatical form across items ("Day / Week / Month", not "Day / Show weeks / Month"). Two to five items; more becomes a Select (3.5).
6. **Accessibility.** As a view switcher, the group is one tab stop and arrow keys move between items; as a toolbar, each item is a button and the group has an accessible name. Icon-only items need an accessible name (shown with a Tooltip (2.13) in the example). Selected state is announced, not shown by color alone: the selected fill plus the darker label give two cues.
7. **Do / don't** (each a pair of instances with `Doc/Do-dont`):
   - Do keep one selected item. Don't select two items in a view switcher.
   - Do let the group draw one border. Don't place bordered Buttons side by side (doubled borders).
   - Do keep inner corners square. Don't round every segment.
   - Do use icon-only segments for well-known formatting icons. Don't use icon-only for actions without a common icon.
8. **Maintenance.** Change segment look in `.Main/Button group item`; change the outer border or radius in `Button group`; colors come from the semantic tokens in the token map.

# 9. QA

Fail QA when:
- items are hand-built frames instead of `.Main/Button group item` instances;
- two borders show between adjacent items;
- inner corners are rounded;
- `Selected` and `State=focus` look the same;
- the focus ring is clipped by the group or hidden by the next item;
- the item has no `Text padding` wrapper;
- the group is rebuilt as tabs with a different anatomy;
- the item matrix is missing a `State`, `Size`, `Icon only` or `Selected` value.
