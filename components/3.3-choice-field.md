# 3.3 Choice field

Choice fields are the labelled versions of the choice Parts. A **Choice field** puts a Checkbox (2.7), Radio (2.8) or Switch (2.9) next to its label and supporting text. A **Choice card** is a richer option with an icon, avatar or payment mark and room for supporting information. A **Choice group** stacks Choice cards into one set of options.

Use a Checkbox for zero or more choices saved with a form, a Radio for exactly one choice from a short list, and a Switch for a setting that takes effect immediately. Use Choice cards when each option needs more explanation than one line, such as plans, payment methods or delivery speeds. Use a Select (3.5) when the options don't fit on screen.

Family header descriptions:
- **Choice field** — "A checkbox, radio or switch with its label and supporting text. The whole row is one click target, and the control stays aligned to the first line of text however long the description is."
- **Choice card** — "Option cards that give each choice room for a title, a short description and a leading icon, avatar or payment mark, without cluttering the layout. Selection shows as a brand border plus the control inside the card."
- **Choice group** — "A set of Choice cards that work as one question: one selection for radio semantics, several for checkbox semantics. The layout adapts for mobile and desktop instead of scaling down."

# 4. Choice field

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Type` | variant | `checkbox, radio, switch` | `checkbox` |
| `Size` | variant | `sm, md` | `md` |
| `Checked` | variant | `false, true, mixed` (`mixed` only for `checkbox`) | `false` |
| `State` | variant | `rest, hover, focus, disabled` | `rest` |
| `Text` | text | — | `Remember me` |
| `Supporting text` | text | — | `Save my login details for next time.` |
| `Show supporting text` | boolean | — | `true` |

Variants: checkbox 2 × 3 × 4 = 24, radio 2 × 2 × 4 = 16, switch 2 × 2 × 4 = 16 → **56**.

A control with no visible text is the Part itself (2.7, 2.8, 2.9); the Choice field always has text.

## Anatomy

```text
Choice field
layout: Horizontal, align Top, gap per Size, Hug width (Fill in layouts), Hug height

├─ Control wrapper               Horizontal, align Center, Hug width, Fixed height = first line height
│  └─ Checkbox | Radio | Switch  Part instance, matching Size / Checked / State
└─ Text and supporting text      Vertical, gap 0, Fill
   ├─ Text                       type/body/{sm|md}/medium
   └─ Supporting text            type/body/{sm|md}/regular        Show supporting text
```

- The control is **top-aligned** to the first line of text, never centred against a multi-line description. The `Control wrapper` is exactly as tall as the first line of `Text` (20 at `sm`, 24 at `md`) and centres the control inside it, so a 16 checkbox, a 20 switch or a slim switch all sit on the first line without manual offsets.
- The text stack fills the remaining width and wraps. Supporting text never moves the control.
- The whole row is the click target: clicking the text toggles the control.

## Sizes and measurements

| Size | Checkbox / Radio | Switch (default) | Gap | Text style | Supporting text style | Control wrapper height |
| --- | --- | --- | --- | --- | --- | --- |
| `sm` | 16 | 36 × 20 | `space/md` = 8 | `type/body/sm/medium` (14 / 20) | `type/body/sm/regular` | 20 |
| `md` | 20 | 44 × 24 | `space/lg` = 12 | `type/body/md/medium` (16 / 24) | `type/body/md/regular` | 24 |

Control sizes come from the Parts; the values above are their defaults. A `switch` field's Switch instance is exposed, so designers can pick `Type=slim` on it.

## States

| State | Control | Text | Supporting text |
| --- | --- | --- | --- |
| `rest` | rest | `color/text/secondary` | `color/text/tertiary` |
| `hover` | hover (the row hover is shown on the control) | `color/text/secondary` | `color/text/tertiary` |
| `focus` | focus ring on the control | unchanged | unchanged |
| `disabled` | disabled | `color/text/disabled` | `color/text/disabled` |

Checked and indeterminate:
- `checkbox` supports `false`, `true` and `mixed`. `mixed` is for a parent whose children are partly selected.
- `radio` supports `false` and `true` only. A radio has no mixed state in product use: a radio question is always answered by exactly one option or none.
- `switch` supports `false` and `true`; the change applies immediately.

# 5. Choice card

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Type` | variant | `icon, icon-card, avatar, payment, radio, checkbox` | `icon` |
| `Size` | variant | `sm, md` | `md` |
| `Selected` | variant | `false, true` | `false` |
| `State` | variant | `rest, hover, focus` | `rest` |
| `Breakpoint` | variant | `mobile, desktop` | `desktop` |
| `Text` | text | — | `Basic plan` |
| `Subtext` | text | — | `$10/month` |
| `Supporting text` | text | — | `Includes up to 10 users, 20 GB individual data and access to all features.` |
| `Show badge` | boolean | — | `false` |

Variants: 6 × 2 × 2 × 3 × 2 = **144**.

## Anatomy

```text
Choice card
layout: Horizontal, align Top, padding per Size, gap per Size, Fill width, Hug height
radius: radius/surface; stroke inside: border/width/default (selected: border/width/strong)

├─ Leading                       type-driven
│  ├─ Featured icon              instance 2.19                    icon
│  ├─ Avatar                     instance 2.6, Size=md            avatar
│  ├─ Payment mark               instance from 1.8, 46 × 32       payment
│  ├─ Radio                      instance 2.8, offset to first line   radio
│  └─ Checkbox                   instance 2.7, offset to first line   checkbox
├─ Content                       Vertical, gap space/xxs, Fill
│  ├─ Title row                  Horizontal, gap space/xs, wrap   (Vertical on mobile)
│  │  ├─ Text                    type/body/{sm|md}/medium
│  │  ├─ Subtext                 type/body/{sm|md}/regular
│  │  └─ Badge                   instance 2.4                     Show badge
│  └─ Supporting text            type/body/{sm|md}/regular, wraps
└─ Selection                     instance 2.8 Radio, Size=sm      icon, avatar, payment
```

`icon-card` is the stacked form for plan pickers:

```text
Choice card (Type=icon-card)
layout: Vertical, gap space/lg
├─ Header                        Horizontal, space-between
│  ├─ Featured icon              instance 2.19
│  └─ Selection                  instance 2.8 Radio
└─ Content                       as above
```

- `Content` fills the width; leading visuals and the trailing selection control stay fixed.
- Text stays on one left edge across all six types: changing the leading visual never shifts the title.
- `radio` and `checkbox` cards put the control first and have no trailing selection; the control is the selection cue.
- `checkbox` cards are the only card type with multi-select semantics. Use them on purpose, never inside a radio question.

## Breakpoint

| | desktop | mobile |
| --- | --- | --- |
| Padding | `space/xl` = 16 (sm), `space/2xl` = 20 (md) | `space/lg` = 12 (sm), `space/xl` = 16 (md) |
| Gap | `space/md` = 8 (sm), `space/lg` = 12 (md) | `space/md` = 8 |
| Title row | Text, Subtext and Badge on one line | Text and Badge on one line, Subtext below |
| Supporting text | full | full, wraps to the narrower width |

Mobile is its own layout, not the desktop card scaled down.

## States

| | Border | Fill | Text |
| --- | --- | --- | --- |
| `rest` | `color/border/default`, 1 | `color/surface/base` | Text `color/text/secondary`, Subtext and Supporting text `color/text/tertiary` |
| `hover` | `color/border/strong`, 1 | `color/surface/base` | unchanged |
| `focus` | rest border + `focus/default` | `color/surface/base` | unchanged |
| `Selected=true` | `color/border/brand`, `border/width/strong` (2), inside so the card does not grow | `color/surface/base` | Text `color/text/brand`; the control inside is `Checked=true` |

Selected and focused are always visibly different: selection is a thicker brand border plus a checked control; focus is the focus ring around the card.

# 6. Choice group

## Properties

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Type` | variant | `icon, icon-card, avatar, payment, radio, checkbox` | `icon` |
| `Size` | variant | `sm, md` | `md` |
| `Breakpoint` | variant | `mobile, desktop` | `desktop` |
| `Show label` | boolean | — | `false` |

Variants: 6 × 2 × 2 = **24**.

## Anatomy

```text
Choice group
layout: Vertical, gap space/lg, Fill width, Hug height

├─ Label                         instance 2.11                    Show label
└─ Items                         Vertical, gap space/lg (icon-card on desktop: Horizontal, equal Fill widths)
   ├─ Choice card                Selected=true
   ├─ Choice card
   └─ Choice card
```

- Default content: three cards of the group's `Type`, `Size` and `Breakpoint`, the first one selected.
- Items are always Choice card instances; designers add or remove cards without detaching.
- `icon-card` groups sit side by side on desktop and stack on mobile; every other type stacks.

# 7. Matrix layout

`Choice field`:
- one block per `Type`;
- columns `State`; rows `Size` → `Checked`;
- under each block, the same field with `Show supporting text` off.

`Choice card`:
- one block per `Type`;
- columns `State` → `Selected`; rows `Breakpoint` → `Size`;
- one card per block with `Show badge` on.

`Choice group`: columns `Breakpoint`; rows `Type` → `Size`.

Axis labels with `Doc/Axis label`.

# 8. Guidelines

Topics in `3.3 Choice field · Guidelines`, in order, each with a visual built from real instances:

1. **Checkbox, radio or switch.** Three columns, one Choice field of each type with its rule: "zero or more, saved with the form" / "exactly one" / "on or off, right away".
2. **Checked, unchecked, mixed.** A parent checkbox in all three states above its children. Caption: "Mixed means some children are selected. Radios never show mixed."
3. **Top alignment.** A Choice field with a three-line supporting text, with a `Doc/Measure` on the control wrapper height. Do: control on the first line. Don't: control centred against the paragraph.
4. **Choice cards.** All six card types in a column, with a callout showing the shared left edge of the titles.
5. **Selected vs focus.** Four cards: rest, selected, focused, selected + focused.
6. **Mobile and desktop.** The same group at both breakpoints side by side. Caption: "Mobile rearranges the title row; it is not the desktop card scaled down."
7. **Content.**
   - Write labels as positive statements ("Send me updates", not "Don't send me updates").
   - Switch labels name the setting, not the action ("Dark mode", not "Turn on dark mode").
   - Card titles are short; supporting text is one or two sentences.
   - Keep option order logical: most common first, or a natural order (small → large).
8. **Accessibility.**
   - The whole row is the target: on touch platforms the row is at least `size/touch-min` high.
   - A group of radios or cards has a group label (the Choice group's Label, or a heading) so screen readers announce the question.
   - Arrow keys move between radios in a group; Tab moves between checkboxes. Space toggles.
   - Selection is never shown by colour alone: the control's mark and the thicker border both change.
   - Switches announce their on/off state; the label stays the same in both states.
9. **Do / don't** (`Doc/Do-dont` pairs):
   - Do use a radio for one choice. Don't use checkboxes for a single choice.
   - Do keep a visible label. Don't show a bare control with no text in a form.
   - Do select one card in a radio group. Don't show two selected radio cards.
   - Don't use focus as selection.
   - Do design the mobile layout. Don't shrink the desktop card.
   - Do use a switch for instant settings. Don't use a switch in a form that saves on submit.
10. **Maintenance.** Control looks live in the Parts (2.7, 2.8, 2.9); the row layout and card styles live here and use the semantic tokens in the token map.

# 9. QA

Fail QA when:
- a control is redrawn or detached instead of a Part instance;
- checkbox and radio fields use controls from different sources;
- `Checked=mixed` is missing for checkbox or offered for radio;
- the control is centred against multi-line text instead of top-aligned;
- supporting text moves the control;
- Selected and focus look the same on a card;
- a leading visual change shifts the card text;
- mobile cards are the desktop cards scaled down;
- supporting text is removed from rich card types;
- group children are detached copies instead of Choice card instances;
- `Choice field` shows a `State` that does not match the control instance inside it.
