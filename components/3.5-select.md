# 3.5 Select

A Select lets people pick one value from a list that may be long; a Multi-select lets them pick several, shown as tags, and search the list. Both are complete form fields: **Label** on top, the **trigger** in the middle, **Help text** underneath, and the option **list** that opens below the trigger.

Use a Select when there are more than about five options or when space is tight. Use Radios in a Choice field (3.3) when five or fewer options should all stay visible, a Menu (3.6) for actions rather than values, and a Text field (3.2) when people type a free value.

## Anatomy

```text
Select
layout: Vertical, gap space/sm, width `size/width/xxs` = 320 in the set (Fill in layouts), Hug height

├─ Label                         instance 2.11                          Show label
├─ Trigger                       Text control 2.10 (or .Main/Select tag box for tags), Fill width
├─ Help text                     instance 2.12                          Show hint (hidden when Open)
└─ List                          Open=true only; Vertical, Fill width, padding-y space/xs, max height `select/list/max-height` = 320
   │                             fill color/surface/raised, stroke color/border/subtle, radius/surface, elevation/overlay
   ├─ .Main/Select option        Selected=true
   ├─ .Main/Select option × 5
   └─ Scroll bar                 .Main/Select scroll bar, absolute, trailing edge          Show scroll bar
```

- The open state **extends** the Select with its list directly under the trigger, `space/xs` below it. It is not a separate component placed next to it.
- The list matches the trigger width.
- The variant hugs the open list so nothing is clipped.

## Sizes and measurements

Trigger heights come from the Text control: `sm` 36, `md` 40, `lg` 44. Field gap `space/sm` = 6. Default width 320.

## .Main/Select scroll bar

One component, no variants: a 4-wide thumb (`radius/full`, `color/fill/neutral/track`) with no visible rail, inset `space/xs` from the list edge, with extra bottom padding `space/xs` so the thumb never touches the list's bottom corner.

| Option state | Content fill | Text | Check / checkbox |
| --- | --- | --- | --- |
| `rest` | `color/fill/none` | `color/text/primary` | — |

- `Select`: one block per `Type`; columns = the eight looks in the order of the table in §4; rows `Size`. Open variants leave room below so lists don't overlap the next row.

# 8. Guidelines

Topics in `3.5 Select · Guidelines`, in order, each with a visual built from real instances:

1. **Select, radios or menu.** A Select, a radio Choice group and a Menu for similar content, each with its rule: "a value from a long list" / "a value from a few visible options" / "an action".
2. **Trigger and list.** A closed and an open Select with callouts on the trigger, the `space/xs` gap and the list matching the trigger width.
3. **Option rows.** The four option types stacked with a vertical guide on the text edge. Caption: "Leading visuals never move the text."
4. **Long selected values.** A trigger with a long name truncated with an ellipsis, and a Multi-select with seven tags wrapped onto two lines. Caption: "Single values truncate; tags wrap and grow the field down."
5. **Search and empty state.** A Multi-select open with a typed query, and the empty state for no matches.
6. **Invalid.** A required Select left empty, with `Status=invalid` and Help text "Choose a timezone."
7. **Content.** Placeholders say what to choose ("Select a timezone"); order options logically (alphabetical, most used first, or natural order); keep option labels short and unique.
8. **Accessibility.**
   - The Label names the select; the chosen value is announced with it.
   - Enter, Space or Down opens the list; arrow keys move; Enter chooses; Escape closes and returns focus to the trigger; typing jumps to matching options.
   - In a Multi-select, each tag's remove button has a name ("Remove Design") and Backspace in the empty search removes the last tag.
   - Selected options are announced; the check and the checkbox give a non-colour cue.
9. **Do / don't** (`Doc/Do-dont` pairs):
   - Do open the list under the trigger. Don't show a detached list floating elsewhere.
   - Do build rows from the option parts. Don't duplicate rows by hand.
   - Do use checkboxes in a Multi-select. Don't use single-select rows for multiple choices.
   - Do let tags wrap. Don't clip chosen values.
10. **Maintenance.** Trigger looks come from the Text control (2.10); option rows, tag box and scroll bar live in `.Main` here; list surface tokens are shared with Menu (3.6).

# 9. QA

Fail QA when:
- the open state is a separate list component instead of the List inside the open variant;
- option rows are drawn by hand instead of option part instances;
- text alignment drifts between `default`, `icon`, `avatar` and `dot` rows;
- Multi-select uses single-select rows without checkboxes;
- chosen values cannot wrap, or long values are clipped instead of truncated;
- the tag box uses different tokens from the Text control;
- an open list is clipped;
- the trigger is a drawn box instead of a Text control instance.
