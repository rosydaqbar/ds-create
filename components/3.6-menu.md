# 3.6 Menu

Menus group related actions or options in a compact panel that opens from a trigger. A **Menu** opens from a button, icon button, link, avatar or account card. A **Context menu** opens on right-click or long-press and exposes secondary actions without taking permanent space.

Use a Menu for actions ("Edit, Duplicate, Delete") and for switching accounts or workspaces. Use a Select (3.5) when the user picks a value for a form field, a Button group (3.1) when two to five actions should stay visible, and a Context menu only for shortcuts to actions that are also available elsewhere.

## Anatomy

`Open=false` contains the trigger only. `Open=true`:

```text
Menu
layout: Vertical, gap space/xs, Hug (start-aligned; icon triggers end-aligned)

├─ Trigger                       Part instance or .Main/Menu account trigger
└─ Panel                         Vertical, width `menu/width` = 240 (account-card types: trigger width), Hug height
   │                             fill color/surface/raised, stroke color/border/subtle, radius/surface, elevation/overlay
   ├─ Header                     .Main/Menu header                 advanced, search, integrations, account types
   ├─ Items                      Vertical, padding-y space/xs, Fill
   │  ├─ .Main/Menu item
   │  ├─ .Main/Menu item
   │  ├─ .Main/Menu item         Type=divider
   │  └─ …
   ├─ Scroll bar                 .Main/Menu scroll bar, absolute, trailing edge   Show scroll bar
   └─ Footer                     .Main/Menu footer                 advanced, search-advanced, account types
```

- The open panel is built only from the private items, headers and footers. Rows are never hand-drawn.
- The variant hugs the full open panel: nothing is clipped, in the component set or in an instance.
- Items fill the panel width; the panel width is fixed (`menu/width` = 240 by default) so rows of different lengths line up.

```text
.Main/Menu item
layout: Horizontal, Fill width, padding space/xxs × space/sm (outer inset)

└─ Content                       Horizontal, align Center, gap space/md, Fill, padding space/md, radius/control
   ├─ Leading                    .Main/Menu item leading, Fixed        Show leading

   ├─ Shortcut                   Kbd (2.17) instance, Fixed            Show shortcut
   └─ Chevron                    Icon/arrows/chevron-right, size/icon/sm, Fixed   Show chevron
```

```text
.Main/Menu item (Type=divider)
layout: Vertical, Fill width, padding-y space/xs
└─ Divider                       Divider (2.16) instance, Fill
```

- The **text is the flexible part**; leading, shortcut and chevron keep their size.
- The divider is an item with its own vertical padding, so it follows the item rhythm. It is never a loose line placed between rows.
- Default row height: 40 (2 outer + 8 + 20 line + 8 + 2).

| Property | Type | Values |
| --- | --- | --- |
| `Type` | variant | `spacer, icon, check, checkbox, dot, avatar, integration` |

```text

Fixed 16 × 16 (avatar and integration: 20 × 20), align Center
└─ spacer: empty · icon: Icon instance size/icon/sm · check: Icon/general/check in color/icon/brand
```

This part keeps the text on the same left edge in every row. A row with no icon in a menu that has icons uses `Type=spacer`; never remove the leading slot and nudge the text by hand. Within one menu, all rows use leading types of the same width.

# 7. States

| Item state | Content fill | Text | Leading icon | Shortcut |
| --- | --- | --- | --- | --- |
| `rest` | `color/fill/none` | `color/text/secondary` | `color/icon/tertiary` | from Kbd |
| `hover` (and `Open=true`) | `color/fill/neutral/subtle/hover` | `color/text/primary` | `color/icon/secondary` | from Kbd |
| `disabled` | `color/fill/none` | `color/text/disabled` | `color/icon/disabled` | hidden |
| `Tone=danger` | rest / hover as above | `color/text/danger` | `color/icon/danger` | from Kbd |

Keyboard focus in a menu moves the hover look; there is no separate focus ring on items. The trigger shows its own focus ring.

# 8. Matrix layout

- `Menu`: two rows (`Open=false`, `Open=true`), columns `Type` in the order of the property table. Open variants are laid out with enough space below so no panel overlaps the next.
- `Context menu`: columns `Type`, rows `Open`.
- `.Main`: item (columns `State` → `Open`; rows `Tone`, then the divider), item leading (one row of all types, each inside a sample item for alignment), header (row of types, then with supporting text off), footer, account item (columns `State`, rows `Selected`), account trigger (columns `State`, rows `Type`), scroll bar.

# 9. Guidelines

Topics in `3.6 Menu · Guidelines`, in order, each with a visual built from real instances:

1. **Menu or context menu.** A row-actions Menu next to a Context menu over the same row. Caption: "Context menus are shortcuts; every action in one must also be reachable from a visible control."
2. **Trigger and panel.** A closed and an open Menu side by side with a callout on the `space/xs` gap and the panel aligned to the trigger edge.
3. **Item anatomy.** One item with callouts on leading, text, shortcut and chevron; a `Doc/Measure` on the outer inset and inner padding.
4. **Leading alignment.** A menu mixing icon rows and spacer rows, with a vertical guide on the text edge. Do: spacer keeps text aligned. Don't: icon removed and text shifted left.
5. **Leading types.** Check, checkbox, dot, avatar and integration rows, each in a short sample menu.
6. **Dividers and groups.** A menu split into three groups with divider items. Caption: "Group related actions; keep each group to a few items."
7. **Danger actions.** A menu ending with "Delete" in `Tone=danger` after a divider. Caption: "Put destructive actions last, separated, and confirm them in a dialog."
8. **Content.**
   - Item labels start with a verb for actions ("Duplicate", "Move to…"); use an ellipsis when the item opens a dialog that asks for more input.
   - Sentence case, no full stops.
   - Keep menus short: about seven items per group; long lists belong in a Select with search.
9. **Accessibility.**
   - The trigger announces that it opens a menu and whether it is open.
   - Arrow keys move between items, Enter or Space activates, Escape closes and returns focus to the trigger, typing a letter jumps to the matching item.
   - The menu has a name (from its trigger); checked items announce their state.
   - Icon-only triggers have an accessible name ("More actions") and a Tooltip (2.13).
   - The open menu stays within the viewport; it flips above the trigger near the bottom edge.
10. **Do / don't** (`Doc/Do-dont` pairs):
    - Do build rows from the item part. Don't hand-draw rows.
    - Do keep leading content aligned. Don't mix aligned and unaligned rows.
    - Do let the menu show completely. Don't clip an open menu inside its container.
    - Do separate destructive items. Don't put "Delete" between "Edit" and "Duplicate".
11. **Maintenance.** Change rows in `.Main/Menu item` and `.Main/Menu item leading`; headers and footers in their parts; panel look through the tokens above. Every Menu and Context menu updates together.

# 10. QA

Fail QA when:
- menu rows are drawn by hand instead of `.Main/Menu item` instances;
- text loses alignment between rows with and without leading content;
- a divider is a loose line outside the item rhythm instead of an item with `Type=divider`;
- account items do not reuse Avatar and Radio;
- the search header is a drawn box instead of a Text control;
- an open menu is clipped in the set or in an instance;
- Context menu uses a different item system from Menu;
- only one generic menu is built instead of every `Type`.
