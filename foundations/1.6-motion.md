# 1.6 Motion

The Motion page shows how long things take and how they move: durations, easing curves, delays, and which pairing to use for each kind of change. Motion explains change: where something came from, where it went, what responded. It also shows the reduced-motion version, so every transition has a fallback before any component uses it.

Build this page only when motion is in scope.

# Template frames


## .Main

- `.Main/Motion bar`: token name → a bar whose length in pixels equals the duration in milliseconds (fill `color/fill/brand/solid`, height `size/track/md`, radius `radius/full`) → value.
- `.Main/Motion curve`: a square plot (stroke `color/border/subtle`) with the easing curve drawn in `color/border/brand` at `border/width/focus` and its two control points marked. Curves that overshoot extend above the plot; the frame does not clip.
- `.Main/Motion sample`: two variants, `Value=start` and `Value=end`: a `size/control/md` square (fill `color/fill/brand/solid`, radius `radius/control`) at the start or end of a track (fill `color/surface/sunken`, width `size/measure/reading`). The prototype goes from `start` to `end` with smart animate, using the duration and easing of the row it sits in.

## · Overview

### 1. Durations

Block note: `Duration`, badge `Variables`. One `.Main/Motion bar` per duration, shortest first.

| Token | Default | Feels like |
| --- | --- | --- |
| `motion/duration/instant` | 0 ms | no animation |
| `motion/duration/fast` | 120 ms | immediate response: hover, press, color change |
| `motion/duration/base` | 200 ms | small movement: a switch thumb, a checkbox mark, a menu opening |
| `motion/duration/slow` | 300 ms | large movement: a dialog or drawer entering |
| `motion/duration/loop` | 900 ms | one rotation of a spinner |

A calmer brand uses shorter, gentler values; a livelier brand uses longer values and curves with a small overshoot.

### 2. Easings

Block note: `Easing`, badge `Variables`. One `.Main/Motion curve` per easing, labelled with its cubic-bezier values.

| Token | Default | Used for |
| --- | --- | --- |
| `motion/easing/standard` | 0.2, 0, 0, 1 | things changing in place |
| `motion/easing/enter` | 0, 0, 0.2, 1 | things arriving: starts fast, settles gently |
| `motion/easing/exit` | 0.4, 0, 1, 1 | things leaving: starts gently, speeds away |
| `motion/easing/linear` | 0, 0, 1, 1 | continuous rotation and progress only |

### 3. Pairings

Block note: `Pairings`. One row per purpose: purpose label → duration chip → easing chip → a `.Main/Motion sample` that plays the pairing in prototype mode.

| Purpose | Duration | Easing |
| --- | --- | --- |
| Hover, press, color change | `fast` | `standard` |
| Switch thumb, checkbox mark, tab indicator | `base` | `standard` |
| Menu, tooltip, popover entering | `base` | `enter` |
| Dialog, drawer entering | `slow` | `enter` |
| Anything leaving | `fast` | `exit` |
| Spinner rotation | `loop` | `linear` |

A second set of rows repeats the pairings in the `Reduced` mode.

## · Tokens

The `Motion` collection, one table per group. It has two modes, `Standard` and `Reduced`, so each table has two value columns with `Doc/Alias chip` value chips (`200 ms`, `0.2, 0, 0, 1`).

| Name | Standard | Reduced | Usage |
| --- | --- | --- | --- |
| `motion/duration/instant` | 0 | 0 | Changes that happen with no animation. |
| `motion/duration/fast` | 120 | 120 | Hover, press and color changes; anything leaving. Kept in Reduced because it is used for fades. |
| `motion/duration/base` | 200 | 0 | Small movements such as a switch thumb or a menu opening. |
| `motion/duration/slow` | 300 | 0 | Large movements such as a dialog or drawer entering. |
| `motion/duration/loop` | 900 | 1800 | One rotation of a spinner; slower, not stopped, in Reduced. |
| `motion/easing/standard` | 0.2, 0, 0, 1 | same | Elements changing in place. |
| `motion/easing/enter` | 0, 0, 0.2, 1 | same | Elements arriving on screen. |
| `motion/easing/exit` | 0.4, 0, 1, 1 | same | Elements leaving the screen. |
| `motion/easing/linear` | 0, 0, 1, 1 | same | Continuous rotation and progress. |
| `motion/delay/tooltip` | 400 | 400 | Wait before a tooltip appears on hover. |
| `motion/delay/toast` | 5000 | 5000 | Time before a toast dismisses itself. |
| `motion/delay/debounce` | 250 | 250 | Wait after typing before a search runs. |

Motion variables are applied to the prototype transitions of interactive components and handed to code; they are not bound to layer properties.

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption.

### 1. Motion explains change

Use motion to show what changed and where it went, never as decoration. A menu grows from its trigger; a dialog rises into place; a removed row collapses so the list closes the gap. Motion never delays the user: the result is available the moment they act, while the transition plays.

**Visual: with and without.** A list where a row is removed, shown as three frames (before, during, after) with the collapse labelled, next to the same change with no motion, where the rows jump.

### 2. Pick the pairing by purpose

Use the pairing table, not a duration picked by feel.
- `enter` for things arriving, `exit` for things leaving, `standard` for things changing in place.
- Exits are faster than entries: anything leaving uses `fast`.
- Larger or farther movement takes longer (`slow` for dialogs and drawers); small feedback such as hover and press stays `fast`.

**Visual: pairing map.** Real components on a timeline: a button hover (`fast · standard`), a menu opening (`base · enter`), the same menu closing (`fast · exit`), a dialog entering (`slow · enter`), each bar drawn to its duration so the differences are visible.

### 3. What to animate

Animate opacity, position and scale. Never animate the size of text or the layout of content someone is reading. Keep one thing moving at a time per area of the screen.

**Visual: do and don't.** `Doc/Do-dont` pairs: a popover fading and scaling from its trigger (do) vs a paragraph reflowing as its container animates width (don't).

### 4. Reduced motion

People can ask their device to reduce motion. In the `Reduced` mode, movement is replaced by an instant change or a short fade: `base` and `slow` become 0, `fast` stays for fades, and spinners keep turning at half speed because they show that something is happening. No information is carried by motion alone.

**Visual: Standard vs Reduced.** The pairing rows played in both modes side by side, with the reduced version of each labelled (`fade`, `instant`, `slower loop`).

### 5. Motion accessibility

- No transition flashes more than three times per second.
- Nothing loops forever without a way to pause or stop it, except progress indicators that end when the task ends.
- Auto-dismissing messages (`motion/delay/toast`) pause while hovered or focused, and important messages never dismiss themselves.

**Visual: accessible loops.** A spinner, an auto-playing carousel with its pause control, and a toast with its hover-pause state, each labelled with the rule it follows.

# QA

- Every duration, easing and delay appears in the Overview with its value.
- Every pairing has a playable sample in both modes.
- Interactive components use the pairing for their purpose in prototype transitions.
- Guidelines fail QA when a topic is text only or the reduced-motion version is missing.
