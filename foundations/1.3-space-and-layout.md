# 1.3 Space & layout

The Space & layout page shows the spacing scale, the size groups (controls, icons, avatars, indicators, tracks, widths, containers, reading measure), and the breakpoints and grids pages are laid out on. Space, sizes and grids stay together on this one page; radius and border widths live on `1.4 Shape`.

```text
Primitives (scale/space/*, scale/size/*)
        ↓ aliases
Space collection (space/*)       gaps and padding
Size collection (size/*)         heights, widths, containers, reading measure, touch minimum
        ↓ bound by
Components, layouts, grid styles (grid/*)
```

## · Overview

### 1. Space scale

Block note: `Space`, badge `Variables`. One `Doc/Measure` row per `space/*` token, smallest to largest, then `space/optical`. Each row shows the token, a bar whose width is bound to the token, the value and its multiple of the base unit (`space/xl · 16 · 4×`).

Default scale (base unit 4):

| Token | Value | × base |
| --- | --- | --- |
| `space/none` | 0 | 0 |
| `space/xxs` | 2 | ½ |
| `space/xs` | 4 | 1 |
| `space/sm` | 6 | 1½ |
| `space/md` | 8 | 2 |
| `space/lg` | 12 | 3 |
| `space/xl` | 16 | 4 |
| `space/2xl` | 20 | 5 |
| `space/3xl` | 24 | 6 |
| `space/4xl` | 32 | 8 |
| `space/5xl` | 40 | 10 |
| `space/6xl` | 48 | 12 |
| `space/7xl` | 64 | 16 |
| `space/8xl` | 80 | 20 |
| `space/9xl` | 96 | 24 |
| `space/10xl` | 128 | 32 |
| `space/11xl` | 160 | 40 |
| `space/optical` | 2 | ½ |

The scale comes from, in order: the existing system; the product's needs (density, platforms); and only when neither exists, the default above. Do not copy a numeric series from another system and do not assume every brand uses a base of 4. Whatever the base, the row note states the relationship between the steps.

### 2. Sizes

Block note: `Sizes`, badge `Variables`. One row per size group; each row is `Doc/Row note` → specimens.

| Row | Specimen | Default values |
| --- | --- | --- |
| Control height | one `Doc/Measure` box per step, height bound to the token; a dashed `size/touch-min` square drawn over `md` | `size/control/xs` 32, `sm` 36, `md` 40, `lg` 44, `xl` 48 |
| Icon | the placeholder icon at each step inside a box bound to the token | `size/icon/xs` 12, `sm` 16, `md` 20, `lg` 24, `xl` 32 |
| Avatar | a circle per step | `size/avatar/2xs` 16, `xs` 24, `sm` 32, `md` 40, `lg` 48, `xl` 56, `2xl` 64 |
| Indicator | a dot per step | `size/indicator/xs` 6, `sm` 8, `md` 10, `lg` 12 |
| Track | a bar per step | `size/track/sm` 4, `md` 6, `lg` 8 |
| Touch minimum | the `size/touch-min` square with a control inside it | `size/touch-min` 44 (48 when Android is a target) |

Which icon size each control size uses: control `xs` and `sm` → icon `sm`; `md` and `lg` → icon `md`; `xl` → icon `lg`.

### 3. Widths

Block note: `Widths`. One horizontal bar per `size/width/*` token, labelled with token and value. Used for fixed-width panels, dropdowns, dialogs and sidebars.

Defaults: `size/width/xxs` 320, `xs` 384, `sm` 480, `md` 560, `lg` 640, `xl` 768, `2xl` 1024, `3xl` 1280, `4xl` 1440, `5xl` 1600, `6xl` 1920. Values come from the product's layout system when it has one.

### 4. Containers and reading measure

Block note: `Containers`. One specimen: a container frame at `size/container/max` (drawn scaled to the frame), with its side margins shown as `Doc/Spec label` measurements, and a reading column at `size/measure/reading` centered inside it.

| Token | Default | Usage |
| --- | --- | --- |
| `size/container/max` | 1280 | Maximum width of page content on large screens. |
| `size/container/margin-mobile` | 16 | Side margin of page content on mobile. |
| `size/container/margin-desktop` | 32 | Side margin of page content on tablet and desktop. |
| `size/measure/reading` | 640 | Maximum width of running text: 65–80 characters of body text per line. |

Products with other platform classes (an app with a sidebar, a kiosk, a TV layout) get the equivalent roles for their platforms instead of these exact names. The reading measure comes from the body style, content density, primary platform and localization needs; do not copy another system's reading width.

### 5. Grids

Block note: `Grids`, badge `Styles`. One frame per breakpoint, side by side, each at its specimen width, with its `grid/{breakpoint}` style applied and the columns also drawn with `.Main/Space grid column` instances, because grid styles do not show in exports or screenshots. A label above each frame gives breakpoint, minimum width, columns, gutter and margin.

Default breakpoints:

| Breakpoint | Min width | Columns | Gutter | Margin |
| --- | --- | --- | --- | --- |
| `grid/mobile` | 0 | 4 | `space/xl` (16) | `size/container/margin-mobile` (16) |
| `grid/tablet` | 768 | 8 | `space/2xl` (20) | `size/container/margin-desktop` (32) |
| `grid/desktop` | 1024 | 12 | `space/3xl` (24) | `size/container/margin-desktop` (32) |
| `grid/wide` | 1440 | 12 | `space/3xl` (24) | centered `size/container/max` |

Build only the breakpoints the product's platforms need: responsive web gets all four; desktop web gets desktop and wide; mobile web and native apps get mobile; a tablet app gets tablet. Column counts and breakpoints come from the product when it has its own; never force another system's viewport widths. Each specimen shows container behavior, columns, gutters, margins and the max-width rule.

## · Tokens

Tables in this order. The `Space` and `Size` collections have one mode (`Value`). When the product needs density modes, they become `Compact`, `Comfortable` and `Spacious` columns (see `02 Tokens · Modes`); only control heights, component paddings and row heights change between them.

| Group | Names | Example usage copy |
| --- | --- | --- |
| Space | `space/none` … `space/11xl`, `space/optical` | `space/md`: Gap between an icon and its label inside controls. |
| Control | `size/control/{xs … xl}` | `size/control/md`: Height of default buttons, inputs and selects. |
| Icon | `size/icon/{xs … xl}` | `size/icon/md`: Icons inside md and lg controls. |
| Avatar | `size/avatar/{2xs … 2xl}` | `size/avatar/sm`: Avatars in table rows and comments. |
| Indicator | `size/indicator/{xs … lg}` | `size/indicator/sm`: Status dots in badges and avatars. |
| Track | `size/track/{sm, md, lg}` | `size/track/sm`: Thickness of progress bars and slider tracks. |
| Width | `size/width/{xxs … 6xl}` | `size/width/xs`: Width of dropdown menus and small popovers. |
| Container | `size/container/max`, `margin-mobile`, `margin-desktop` | as in Overview §4 |
| Measure | `size/measure/reading` | as in Overview §4 |
| Touch | `size/touch-min` | Smallest tap target on touch screens; icon-only controls reach it through their hit area. |

Each size group is a parent row (`size/control`, value cell shows the range) with its steps as children drawn with `Doc/Tree connector`. Value cells use `Doc/Alias chip` with the resolved number and the primitive it aliases (`16 · scale/space/16`).

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption, built from this system's components and real token names.

### 1. Why the spacing system matters

A fixed spacing scale removes arbitrary decisions and gives design and code the same rhythm. Without one, every gap is a new choice: padding drifts between screens, edges stop lining up, and developers guess values that don't match.

**Visual: without system vs with system.** The same dialog or card composition twice. *Without system*: uneven gaps and padding, arbitrary values (7, 13, 18), edges that don't line up. *With system*: only scale values, aligned edges, a steady vertical rhythm. `Doc/Spec label` annotations on both show the values used.

### 2. The base unit and the scale

The scale is built from one base unit (4 by default); every step is a simple multiple of it, with `space/xxs` and `space/optical` at half a unit for fine adjustments. Small steps are close together for tight UI; large steps jump further apart for page sections. Each step is named by size (`xs` to `11xl`), not by value, so the scale can change without renaming.

**Visual: scale on the base grid.** The space bars from Overview placed over a base-unit grid, so each bar visibly lands on whole or half units, with the step names and multiples labelled.

### 3. Spacing inside components

Show how the tokens appear in real components, not only as a list.

**Visual: annotated menu.** A real `Menu` instance (or, before Components exist, a menu built from real Parts) with callouts for: item padding (`space/md` / `space/lg`), icon-to-label gap (`space/md`), group spacing (`space/xs`), divider spacing (`space/xs`) and menu inset (`space/xs`). Callouts use the actual token names.

### 4. Optical exceptions

Not every internal value lands on the base grid. Icon live areas and text metrics need optical correction: an icon's glyph does not fill its box, and a label's line height adds space above and below the letters.

**Visual: button padding, three steps**, using the real `Button`:
1. mathematically even padding on both sides of an icon + label button, which looks uneven because of the icon's empty live area;
2. the corrected treatment: the label sits in the `Text padding` wrapper with `space/optical` on both sides;
3. measurement annotations showing outer padding, icon box, glyph live area and the optical inset.

This visual matches the Button anatomy on `2.1 Button`.

### 5. Component padding

A focused example of how the parts of one control add up.

**Visual: button padding anatomy.** One `Button` (`Size=md`) with measurements for outer horizontal padding (`button/padding-x/md`), the icon frame (`size/icon/md`), the label wrapper (`space/optical`), the gap (`space/xs`), and the resulting perceived spacing on each side of the label. It explains the real Button construction, not a generic spacing demo.

### 6. Control sizes and touch targets

Control heights come from `size/control/*`, so every control of the same size lines up in a row: a `md` button, input and select share one height. On touch screens, every tappable element needs a target of at least `size/touch-min`, even when it looks smaller; a compact icon button gets an invisible hit area, never a bigger icon.

**Visual: aligned controls and hit areas.** A toolbar row with a `md` button, text field and select on one baseline, `size/control/md` measured once across all three; then a small icon button with its dashed `size/touch-min` hit area drawn around it.

### 7. Reading width and line length

Running text needs a readable line length. Use the reading measure role (`size/measure/reading`) for body copy instead of letting paragraphs run the full container width.

**Visual: annotated paragraph** at `size/measure/reading`, with the measure and the character count per line labelled.

**Visual: line-length comparison.** The same paragraph in the body style three times: too short (choppy, 30–40 characters), selected (65–80 characters, marked `Selected`), too long (120+ characters, hard to track back to the next line). Each is labelled with its character count.

### 8. Containers and grids

Page container, columns, gutters, section spacing and component alignment work together: the container sets the outer edges, the grid divides it, and components snap to column edges.

**Visual: responsive page on the grid.** One product page (a header, a card row and a form) at desktop, tablet and mobile, each with its `grid/*` columns drawn and labels for container width, margins, gutter and the section gap (`space/7xl`). Uses the real grid values of this system.

### 9. Exceptions and best practices

- Use scale values for every gap, padding and margin. When a design needs a value that is not on the scale, first check whether a neighbouring step works; add a step only when a real, repeated need exists, and add it to the scale, not to one layer.
- Optical corrections (`space/optical`, half steps around icons) are the allowed exception, and they live in component tokens, not in one-off overrides.
- Space between related items is smaller than space between groups: tighter inside a group, looser between groups.
- Keep padding symmetrical unless content forces otherwise (an icon on one side, a text baseline).
- Prefer Auto Layout gap and padding bound to `space/*` over manually placed layers.

**Visual: grouping by spacing.** A settings form where related fields sit `space/lg` apart and sections sit `space/4xl` apart, with callouts; next to it the same form with equal gaps everywhere, where the groups disappear.

### 10. Nudge setting (optional)

An authoring tip, not part of the product system. Set Figma's big nudge to the base unit multiple you use most (`space/md` = 8, or the base unit) so Shift + arrow moves layers along the scale. Show a small editor-settings example. Keep this topic short; it never gets the same prominence as the spacing and grid topics.

# QA

- The Overview shows every `space/*` token as a bound bar, every size group, widths, containers and reading measure, and one grid frame per breakpoint in scope with columns drawn visibly.
- Every bar, box and grid gutter is bound to its token.
- Grid styles bind gutter and margin to space and container tokens.
- The Tokens tables show every size group as a tree with connectors.
- Guidelines fail QA when a topic is text only, there is no without/with-system comparison, spacing is not shown inside a real component, optical exceptions are not shown visually, reading-width guidance has no line-length comparison, or the grid example does not use this system's real values.
