# 1.8 Brand assets

The Brand assets page holds artwork that cannot be expressed in tokens: the product's own logos, third-party logos, social and integration marks, app icons and app-store badges, payment marks, flags, file-type and folder marks, and emoji. It is the only page where raw colors and geometry are allowed, because the artwork belongs to its owners.

Every asset comes from the user. Never invent a logo, flag or third-party mark, and never redraw one from memory. If the product logo is missing, ask; if the user says to continue without it, build a clearly marked placeholder (the product name set in `type/heading/md/semibold`, `color/text/primary`) and list it as a placeholder.

This page owns no variables, so it has no Tokens frame.

## .Main

- `.Main/Asset cell`: an asset instance above its variant name in `type/code/sm/regular`, `color/text/tertiary`, padding `space/lg`, gap `space/xs`.
- `.Main/Asset surface`: a frame (padding `doc/space/row`, radius `doc/radius/surface`) that holds a row of cells; fill `color/surface/base` for light versions, `color/surface/inverse` for dark versions.

## · Overview

One section per asset kind, in this order. Each section has a `Doc/Block note` (what the assets are, where they come from, how many), then the published set with a `Doc/Family header` and its matrix laid out with `Doc/Axis label` labels. Light versions sit on a light `.Main/Asset surface`, dark versions on a dark one, with each light/dark pair aligned vertically for comparison. A kind with no supplied assets is left out.

Notes per kind:
- **Product logo**: the product's own logomark and full logo lockup from the user's files. These are the assets other components swap in through their `Logo` property.
- **Partner logos**: `badge` places the mark in a bordered rounded container (`radius/surface`, `color/border/subtle`). The dark version is the owner's dark-surface artwork, not an inverted copy.
- **Social marks**: `Mono=true` is a single-color version with one vector named `Icon`, bound to `color/icon/secondary` (`color/icon/primary` on hover), so it follows the color modes like an icon. `Mono=false` keeps the provider's colors.
- **App-store badges**: the official badge artwork in its official proportions. `solid` is the store's standard black badge; `outline` is its outlined version. Never rebuild a badge from text, a button or an icon.
- **Payment marks**: the card or wallet mark inside a bordered card shape (`color/border/subtle`).
- **Flags**: only the flags the product needs (supported countries, regions, currencies).
- **File types**: a document shape with the extension label; `color` uses the conventional color per type, `neutral` is gray, `solid` is a filled shape with a white label.
- **Folders**: `brand` uses `color/fill/brand/*`, `neutral` uses `color/fill/neutral/*`, `textured` adds a subtle texture, `transparent` is a glass-like version for imagery. The paper layer shows a document peeking out.

Mono marks and brand-colored folders bind their colors to `color/*` roles. All other assets keep their owner's colors as raw values.

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption, built from this file's own assets.

### 1. What is on this page and why

A visible inventory of the asset kinds in scope: which are included, which were skipped on purpose, and why. Each kind lists its intended use (for example "Payment marks: checkout and billing settings", "Flags: country selector and phone input"). Add a new asset kind only when the product needs it; never generate unused artwork to make the library look complete.

**Visual: asset inventory.** One card per asset kind with a sample asset, the count, the components that use it, and its status (`supplied`, `placeholder`, `skipped`).

### 2. Logos are shared assets

Every logo is managed in one place. Replacing one approved asset updates every mockup and component that uses it.

**Visual: shared logo workflow.**

```text
Shared logo component
      ↓
Avatar · Card · Header · Logo cloud instances
```

The source component with connector lines to four real instances; then the same instances after the source logo is replaced. Uses this system's own logo or placeholder.

### 3. Replacing placeholder logos

How to swap a placeholder for the real artwork:
1. find the shared logo component on this page;
2. replace the artwork inside it;
3. keep the container, mask and sizing;
4. check the dependent instances.

**Visual: replacement steps.** Four frames: the placeholder, the source component selected, the new artwork in place, and several dependent instances updated.

### 4. Choose the version by surface

Use the light version on light surfaces, the dark version on dark surfaces, and the mono version when the layout needs one color. Never recolor, invert, outline, add effects to, crop or stretch a logo.

**Visual: do and don't.** `Doc/Do-dont` pairs: the dark version on `color/surface/inverse` (do) vs the light version on the same surface (don't); the logo at its proportions (do) vs stretched (don't); the original colors (do) vs recolored (don't).

### 5. Optical sizing

Logos in identical boxes rarely look the same size. Wide, round, condensed, tall and irregular marks each need their own height to look equal.

**Visual: four steps, all required:**
1. **Not optically resized**: several differently shaped logos forced to one identical height. Some look huge, some tiny.
2. **Optically resized**: the same logos adjusted so they carry similar visual weight.
3. **Sizing heights**: the different heights used, labelled with `Doc/Spec label`.
4. **Alignment lines**: top and bottom visual alignment guides drawn across the set.

The point cannot be made in prose; the visuals are mandatory. Never normalize all marks to one raw pixel height.

### 6. Resizing, clear space and minimum size

Resize logos proportionally only (hold Shift or lock the aspect ratio). Keep clear space around the product logo (by default the height of the logomark on every side) and never use it below its minimum size (by default 16 for the mark, 24 high for the lockup). When an owner publishes their own rules, follow them and note them in the block note.

**Visual: clear space and minimum size.** The product lockup with its clear-space area drawn around it and measured, then the mark and lockup at their minimum sizes; beside them, a stretched logo marked don't.

### 7. Using flags, payment marks, file types and badges

- Flags stand for countries and regions, never languages. A language picker lists language names.
- Payment marks, flags and file-type marks appear with their text label in lists (`Visa ending 4242`, `France`, `report.pdf`), so meaning never depends on the image alone.
- App-store badges are used whole as a link to the store, at `Size=md` or `lg`, with the store's official wording.
- Social sign-in buttons are built as `Social button` (`3.7`) from a `Button` and a `Social mark`, following the provider's own naming rules.

Accessible names: the product name for logos, the country name for flags, the method name for payment marks, the store name for app-store badges, the provider name for social marks. Decorative artwork is hidden from assistive technology.

**Visual: assets in context.** A checkout card with payment marks and labels, a country selector with flags and country names, a file list with file-type marks and names, and an app-download footer with both store badges.

### 8. Licensing and third-party marks

- Use only owned or approved brand marks.
- Record the source and licence of every third-party asset in its block note.
- Third-party marks stay the property of their owners, and showing them in a mockup does not imply endorsement.

Do not build a promotional logo pack or third-party logo library unless the user supplied one.

**Visual: source labels.** The partner logo section with a small source line under each mark (owner, source, licence), as it appears on the page.

### 9. Extending the asset library

Add a new asset (another partner, flag or payment method) as a new value of the existing set's identity property, with every version the set has (`Surface`, `Mono`, `Size`). Add a new asset kind only when several screens need it.

**Visual: adding a variant.** A new partner logo added to `Partner logo` in all four `Type` × `Surface` combinations, next to an existing partner for comparison, then placed in the matrix.

# QA

- Every asset on the page was supplied by the user or is a clearly marked placeholder.
- Each kind is one published set with the properties listed above, shown as a full matrix with axis labels.
- Light/dark pairs line up vertically.
- Mono marks have one vector named `Icon` bound to a `color/icon/*` role.
- Guidelines fail QA when logo management has no replacement workflow visual, optical sizing has no before/after comparison, all marks are normalized to one raw height, or the page includes third-party promotional or logo-pack material the user did not provide.
