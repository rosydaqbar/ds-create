# 1.4 Shape

The Shape page shows corner radius and border widths. Radius is a set of roles, not a numeric scale: controls, indicators, surfaces and dialogs each have one role, so the whole system changes its corner character from one place without editing components. Border widths separate default lines from strong, focus and selected lines.

```text
Primitives (scale/radius/*, scale/border-width/*)
        ↓ aliases
Shape collection (radius/*, border/width/*)
        ↓ bound by
Components
```

## · Overview

### 1. Radius roles

Block note: `Radius`, badge `Variables`. One `.Main/Shape radius tile` per role, in this order, labelled with role and value.

| Role | Default | Used on |
| --- | --- | --- |
| `radius/none` | 0 | tables, full-bleed images, edges that meet other edges |
| `radius/xs` | 4 | small parts inside controls: checkbox box, keyboard keys, small thumbnails |
| `radius/sm` | 6 | small nested parts: menu items, tags inside inputs, slider thumb track |
| `radius/control` | 8 | anything the user operates: buttons, inputs, selects, segmented controls |
| `radius/indicator` | full | badges, tags and status chips |
| `radius/surface` | 12 | containers: cards, panels, menus, popovers |
| `radius/modal` | 16 | dialogs, drawers and sheets |
| `radius/full` | 9999 | pills, avatars, switches, dots, radio buttons |

The tile for `radius/full` and `radius/indicator` (when full) is a pill: width hugs, height `size/control/md`.

Defaults are for a softly rounded system. The brand's corner character sets the values (see Guidelines topic 2). Keep an existing radius scale; otherwise derive it from the chosen corner treatment. Never copy another system's radius values, and never add steps the brand does not use.

### 2. Radius in use

Block note: `Radius in use`. Four groups, each labelled with the role each layer binds:
- a control-height frame (`size/control/md`) with `radius/control`;
- an indicator-height frame (`size/icon/md`) with `radius/indicator`;
- a surface tile with `radius/surface` holding a control frame with `radius/control`, with the padding between them labelled;
- a dialog frame with `radius/modal`.

Built from plain frames bound to the tokens, so the overview works before any Part exists. Real components appear in the Guidelines.

### 3. Border widths

Block note: `Border widths`, badge `Variables`. One `.Main/Shape border line` per token, in this order:

| Token | Default | Used for |
| --- | --- | --- |
| `border/width/default` | 1 | dividers, outlines of controls, cards and menus |
| `border/width/strong` | 1 (2 in high-contrast systems) | emphasized lines: a control on a tinted surface, the active tab underline base |
| `border/width/focus` | 2 | focus outlines, together with the `focus/*` effect styles on 1.5 |
| `border/width/selected` | 2 | selected outlines: a selected radio card, the active segment |

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption, built from this system's components and real token names.

### 1. Radius is a role, not a number

Do not document radius as numbers only. Each role belongs to a kind of element, so a designer picks the role by what the element is, never by eye.
- Bind `radius/control` on everything the user operates, `radius/surface` on containers, `radius/modal` on dialogs and drawers, `radius/indicator` on badges and tags.
- Use `radius/xs` and `radius/sm` only for small parts inside controls and surfaces; never invent a radius between roles.
- Use `radius/full` only for pills, avatars, switches, dots and radio buttons.
- A radius larger than half the shorter side renders as fully round; size the layer so this is intended.
- Never show state through a radius change; states use color and border width.

**Visual: radius specimen.** The role tiles from Overview, each connected to two real components that use it (button and input for `control`; badge and tag for `indicator`; card and menu for `surface`; dialog for `modal`; avatar and switch for `full`). If the brand uses a small radius vocabulary (for example all controls and surfaces square), show only the roles that exist.

### 2. Corner character

Corner radius sets much of a product's feel: square corners read precise and technical, soft corners read friendly, fully round controls read playful and touch-first. The choice applies to the roles together, not to one component.

**Visual: three corner treatments.** The same small composition (a card with a heading, a text field, a badge and a primary button) three times: sharp (`control` 2, `surface` 4), soft (the system defaults) and round (`control` full, `surface` 24). Content and color stay the same. The treatment this system uses is marked `Selected`.

### 3. Nested corners

When a rounded element sits inside another, the outer radius equals the inner radius plus the padding between them, so the two curves stay parallel. When the result would not be a role, use the nearest larger role for the outer element.

**Visual: nested radius.** A card with `radius/surface` holding a button with `radius/control`, shown twice: corners that look pinched (same radius inside and out) and corners that look parallel (outer = inner + padding). `Doc/Spec label` measurements show both radii and the padding.

### 4. Border widths

Most lines in the system use `border/width/default`. Use `strong` only when a line must stand out from its surface, and `focus` and `selected` only for those states. A selected or focused control keeps its size: the wider border is drawn inside the layer, so content never shifts.

**Visual: border widths in use.** A default text field, the same field focused (`border/width/focus` with the `focus/default` ring), a radio card at rest and selected (`border/width/selected`), each labelled with the width and color role it uses. A callout shows the content position unchanged between rest and selected.

### 5. Change shape from the source

Because components bind roles, changing `radius/control` changes every button, input and select at once; changing `border/width/focus` changes every focus outline.

**Visual: propagation.** `radius/control` edited from 8 to 4 in the `Shape` collection, then a button, a text field and a select shown before and after.

# QA

- Every radius role and border width appears in the Overview as a bound tile or line, with name and value.
- No component on any page uses a raw radius or stroke width.
- The radius specimen links each role to real components.
- Guidelines fail QA when radius is shown as numbers only, the corner-character comparison is missing, or a visual uses names that are not this system's token names.
