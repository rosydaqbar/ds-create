# 1.5 Elevation

The Elevation page shows the effect styles: shadows that lift surfaces off the page, focus rings for keyboard navigation, and backdrop blurs. Every effect color is bound to a color role from `1.1 Color`, so palette and mode changes reach every shadow and ring.

```text
Color roles (color/shadow/*, color/border/focus, color/border/danger, color/surface/base)
        ↓ used by
Effect styles (elevation/*, focus/*, blur/*)
        ↓ applied by
Components
```

Effect styles are not variables, so this page has no Tokens frame. The style list and each style's layers are documented on the Overview cards.

## .Main

- `.Main/Elevation shadow card`: a specimen card (size `doc/measure/specimen`, fill the surface role the level is used with, radius `radius/surface`) with the effect style applied, sitting on `color/surface/sunken` so the shadow is visible; under it the style name and one line per effect layer (`y 4 · blur 8 · spread −2 · color/shadow/key`).
- `.Main/Elevation focus card`: a control-height frame (`size/control/md`, radius `radius/control`) with the focus style applied, the style name under it.
- `.Main/Elevation blur card`: a translucent panel with the blur style applied over a busy background (a gradient and text), the style name and radius under it.

## · Overview

### 1. Shadows

Block note: `Elevation`, badge `Effect styles`. One `.Main/Elevation shadow card` per level, lowest first. Each level is always used with its surface role.

| Style | Used by | Surface role |
| --- | --- | --- |
| `elevation/control` | buttons and controls that carry depth | the control's own fill |
| `elevation/raised` | cards and panels above the page | `color/surface/raised` |
| `elevation/overlay` | menus, popovers, tooltips | `color/surface/overlay` (or `color/surface/inverse` for tooltips) |
| `elevation/modal` | dialogs, drawers, sheets | `color/surface/overlay` |

Default recipe (layered depth). Each layer is a drop shadow `x / y / blur / spread` with its color bound to a `color/shadow/*` role:

| Style | Layers |
| --- | --- |
| `elevation/control` | 0 / 1 / 2 / 0 `ambient` |
| `elevation/raised` | 0 / 1 / 2 / 0 `ambient` + 0 / 1 / 3 / 0 `key` |
| `elevation/overlay` | 0 / 12 / 16 / −4 `key` + 0 / 4 / 6 / −2 `ambient` |
| `elevation/modal` | 0 / 20 / 24 / −4 `key` + 0 / 8 / 8 / −4 `ambient` |

Other depth directions:
- **Flat**: `control` and `raised` have no shadow (the border carries the edge); `overlay` 0 / 4 / 8 / 0 `ambient`; `modal` 0 / 8 / 24 / 0 `ambient`.
- **Tactile**: `elevation/control` adds two inner shadows: 0 / −2 / 0 / 0 `color/shadow/edge` (bottom edge) and 0 / 1 / 0 / 0 `color/shadow/highlight` (top highlight).

Keep the brand's existing shadow values when it has them. Never copy another system's shadow values, blur radii or card sizes.

### 2. Focus rings

Block note: `Focus`, badge `Effect styles`. Focus rings are effect styles because a layer can hold only one effect style: a control that has a shadow needs one style that carries both the ring and the shadow. Three groups, each a row of `.Main/Elevation focus card` instances:

| Group | Styles | Layers |
| --- | --- | --- |
| Focus ring | `focus/default`, `focus/danger` | spread 2 `color/surface/base` (the gap) + spread 4 `color/border/focus` or `color/border/danger` (the ring) |
| Focus ring + control shadow | `focus/default/control`, `focus/danger/control` | the ring layers + the `elevation/control` layers |
| Focus ring + tactile control | the same two styles when the tactile treatment is used | the ring layers + the tactile `elevation/control` layers |

The row note explains why the combined styles exist (one effect style per layer). A frame with a focus ring keeps clip content off, so the ring is never cut.

### 3. Backdrop blurs

Block note: `Backdrop blur`, badge `Effect styles`. One `.Main/Elevation blur card` per step, shown once on a light background and once on a dark one.

| Style | Blur | Used by |
| --- | --- | --- |
| `blur/backdrop/sm` | 8 | sticky headers and toolbars over content |
| `blur/backdrop/md` | 16 | floating panels and popovers over media |
| `blur/backdrop/lg` | 24 | full-screen overlays and sheets over imagery |

Built only when a component uses backdrop blur.

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption, built from this system's components and real style names.

### 1. Depth is a choice

A system can be flat, use subtle elevation, use stronger layered elevation, or add a restrained tactile treatment on controls. The brand's chosen visual direction decides which recipe is generated. Never add depth just because other systems do.

In dark mode shadows are much less visible. The `color/shadow/*` roles are stronger in `Dark`, and raised surfaces also step lighter (`color/surface/raised`), so depth reads through surface color as well as shadow.

**Visual: flat vs selected depth.** The same `Button` and card, with the same content, in the flat treatment and in the system's selected treatment, side by side. If the system is flat, show only the flat result and a short note that the effect layer is off.

### 2. Effect-stack anatomy

When the system uses depth, show how each style is built.

**Visual: effect stack.** One card and one button pulled apart into their layers: outer shadow layers, inner highlight and edge (when tactile), the stroke and its `border/width/default`, and the fill. Each layer is labelled with its values, its color role and that role's `Light` and `Dark` alias chips. Show this system's real recipe, not generic values.

### 3. Changing or removing the effect treatment

The effect treatment changes from one place: edit the style (or the color role it uses) and every component updates. Removing the tactile treatment means editing `elevation/control` and the two `focus/*/control` styles, nothing else.

**Visual: propagation.** A row of buttons and cards with the selected effect; the shared style `elevation/control` edited (tactile layers removed); the same instances updated. The visual proves the treatment is central.

### 4. Focus rings

Focus is not hover. Every interactive component needs a visible focus treatment for keyboard and other non-pointer navigation. The ring has a gap in the surface color and then the ring color, so it stays visible on any background.

**Visual: focus grid.** A grid of real focused controls (`Button`, `Text field`, `Checkbox` or `Switch`) on `color/surface/base`, on `color/surface/inverse` or the dark mode, and on `color/surface/brand-subtle`. Callouts name the focus style, the ring width and gap, and the ring's contrast against each surface (at least 3:1).

### 5. Applying and editing focus styles

Apply focus through the component's `State=focus` variant, which uses the matching `focus/*` style; never draw a ring by hand on an instance. Use `focus/danger` on controls with `Status=invalid` and on danger-tone actions. When a control has a shadow, use the `/control` version so the shadow stays.

The ring color is a variable (`color/border/focus`) and the ring width follows `border/width/focus`. Figma cannot bind an effect's spread to a variable, so the ring width is written into the style itself; when `border/width/focus` changes, update the `focus/*` styles in the same step.

**Visual: focus workflow.** `color/border/focus` edited in the `Color` collection, then a focused button, text field and checkbox shown before and after. A callout marks the ring width as the one value that must be updated by hand.

### 6. Shadow and effect color dependencies

Shadows and rings change when the palette changes.

**Visual: palette change.** One raised card and one focused button: their original color roles with swatches, the updated palette, and the effect result after remapping, side by side.

# QA

- Every effect style appears on an Overview card with its name and layers.
- Every shadow color and ring color is bound to a `color/*` role; no raw color in any effect.
- Focus styles exist alone and combined with the control shadow.
- Guidelines fail QA when a topic is text only, the selected depth has no component example, the effect stack is not shown, focus is shown without real focused controls, or central editing is claimed without a propagation example.
