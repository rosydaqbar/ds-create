# 2.19 Featured icon

A Featured icon places a standard icon inside a shaped container so it reads as a visual anchor: at the top of an empty state, a confirmation dialog, a feature list item or a notification. Its `Tone` tells users what kind of message follows; its `Emphasis` sets how loud it is.

Featured icon is how the system gets a larger icon without scaling an icon past its intended size: the icon keeps its designed box and stroke, and the container adds the presence (see `1.7 Iconography`, *Icon sizing*).

Use a plain icon inline with text, and an Icon button (2.2) when the icon is an action.

# 1. Purpose

- Anchor a block of content with a recognizable symbol.
- Signal the message's intent with tone — brand, neutral, danger, warning, success.
- Give larger icon presence without distorting icon strokes.

The styles, heaviest first:

| Type | Emphasis | Container | Icon |
| --- | --- | --- | --- |
| `circle` | `primary` | solid tone fill | on-solid color |
| `circle` | `secondary` (default) | subtle tone fill | tone color |
| `circle` | `tertiary` | no fill; two concentric rings in the tone, the outer one fainter | tone color |
| `square` | `tertiary` | base surface, neutral border, raised shadow, rounded square | tone color |

`Tone` is the semantic intent. A danger message uses `Tone=danger` in the same set, never a separate set.

# 5. Anatomy

## Circle, primary and secondary

```text
Featured icon
layout: Horizontal
align: Center / Center
size: fixed by Size (square box)
radius: radius/full
fill: by Emphasis and Tone

└─ Icon                               instance swap; icon box by Size; color by Emphasis and Tone
```

## Circle, tertiary

```text
Featured icon
layout: none (positioned)
size: fixed by Size
fill: none

├─ Outer ring                         ellipse the full box; stroke 2, inside; fainter tone border
├─ Inner ring                         ellipse inset 4 on every side; stroke 2, inside; tone border
└─ Icon                               centered
```

## Square, tertiary

```text
Featured icon
layout: Horizontal
align: Center / Center
size: fixed by Size
radius: radius/control (sm, md) / radius/surface (lg, xl)
fill: color/surface/base
border: color/border/default, border/width/default, inside
effect: elevation/raised

└─ Icon
```

Construction rules:
- The icon keeps its standard icon box and stroke. Only the container grows with Size.
- The icon is centered optically: for icons whose visual weight is off-center (play, send), nudge inside the icon component, never in the Featured icon.
- The icon color is bound on the Icon instance so swapping the icon keeps the color.

## Auto Layout relationship

Featured icon is a fixed box. In compositions it is the first child of a vertical stack (empty state, dialog) or a horizontal row (feature item, notification), with `space/lg` = 12 to `space/xl` = 16 between it and the text, set by the parent.

## Flexible vs fixed children

| Layer | Horizontal | Vertical |
| --- | --- | --- |
| `Featured icon` (root) | Fixed by Size | Fixed by Size |
| `Icon` | Fixed (icon box) | Fixed (icon box) |
| `Outer ring`, `Inner ring` | Scale with the root | Scale with the root |

# 6. Sizes and measurements

| Size | Container | Icon box | Pairs with |
| --- | --- | --- | --- |
| `sm` | 32 | `size/icon/sm` = 16 | body text rows, notifications |
| `md` | 40 | `size/icon/md` = 20 | feature list items, cards |
| `lg` | 48 | `size/icon/lg` = 24 | dialog and empty-state headings |
| `xl` | 56 | 28 | large empty states and onboarding |

Container sizes live in `featured-icon/size/{size}`; the `xl` icon box in `featured-icon/icon/xl`. Tertiary rings: stroke `border/width/strong` = 2; inner ring inset 4.

# 10. Guidelines content

Topics for `2.19 Featured icon · Guidelines`, in order. Each visual uses real Featured icon instances in real compositions.

## A bigger icon without a bigger icon

Icons are drawn for their box; scaling one far beyond it thickens strokes and blurs details. When an icon needs more presence, place the standard icon in a Featured icon.

Visual — the icon-sizing comparison from the Anatomy frame, annotated: icon box 24, container 48, "strokes and proportions unchanged".

## Tone follows the message

Match the tone to what follows: `danger` for errors and destructive confirmations, `warning` for risk, `success` for completion, `brand` for features and onboarding, `neutral` for everything else. Tone is never the only signal: the heading says the same thing.

Visual — four dialogs in a row (danger "Delete this file?", warning "Unsaved changes", success "Payment received", neutral "No results"), each with its Featured icon and heading.

## Emphasis per screen

Use one emphasis on a screen. Use `primary` only when the Featured icon is the main focal point, `secondary` by default, and `tertiary` next to body text or when several sit together.

Visual — Do/don't pair (`Doc/Do-dont`):
- Don't: a feature list mixing primary, secondary and square styles.
- Do: the same list in `secondary` only.

## Size from the heading

Pick the size from the text it anchors: `sm`–`md` beside body text and list items, `lg` above a dialog or empty-state heading, `xl` for large empty states and onboarding.

Visual — the four sizes, each beside the heading or text level it pairs with.

## Not a button, not inline

A Featured icon is not interactive; when the icon is an action, use an Icon button (2.2). Don't place a Featured icon inside a sentence; use a plain icon.

Visual — Don't: a Featured icon used as a close control. Do: an Icon button with the close icon.

## Accessibility

- Most Featured icons repeat what the heading next to them says and are hidden from assistive technology.
- When the icon is the only signal of the message's intent, it gets an accessible name ("Warning").
- The icon meets the non-text contrast threshold against its container (or against the surface for `tertiary`) in every color mode and tone.

# 11. QA

Fail QA when:
- an icon is scaled up instead of placed in a Featured icon at its standard box;
- the outline style is a separate set instead of `Emphasis=tertiary`;
- danger, warning or success are separate sets instead of `Tone` values;
- the icon color is lost when the `Icon` is swapped;
- rings are drawn as images or flattened vectors instead of bound strokes;
- the container size or icon box differs from §6;
- colors are raw values or opacity tricks instead of the tokens in §9.
