# 4.2 Video player

A Video player shows a video in a 16:9 frame with playback controls on top of it: a large overlay play button and an actions bar with play, volume, a timeline and view controls. It is used for realistic playback mockups in product screens: course lessons, product tours, recorded meetings.

The controls sit **on** the video, not under it. They overlay the 16:9 media frame and never add height to it.

# 3. Composition

| Part | From | Used in |
| --- | --- | --- |
| `Kbd` | 2.17 Kbd | shortcut inside the tooltip ("Space", "M", "F") |
| Icons | 1.7 Iconography | every action |
| `.Main/Video player *` | this page | controls on the media |

The controls are private parts rather than Icon buttons (2.2) or a Slider (2.18) because they sit on video in every color mode: their colors stay light-on-dark whatever the interface mode is, and their tooltips carry a shortcut. Each private part says which Part it mirrors.

# 4. Private parts

## .Main/Video player action

Mirrors Icon button (2.2) for media.

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Type` | variant | `play, pause, rewind, fast-forward, skip-back, skip-forward, volume-none, volume-min, volume-max, zoom-out, zoom-in, cast, minimize, maximize, fullscreen, exit-fullscreen, playback-speed, captions` | `play` |
| `State` | variant | `rest, hover, focus` | `rest` |
| `Size` | variant | `sm, md, lg` | `lg` |

Variants: 18 × 3 × 3 = **162**.

```text
.Main/Video player action
layout: Horizontal, align Center, Fixed square per Size, radius/control

├─ Icon                          per Size, centered (playback-speed: Text "1×" type/body/sm/semibold)
└─ Tooltip                       .Main/Video player tooltip, absolute above the button   State=hover
```

| Size | Button | Icon |
| --- | --- | --- |
| `sm` | 32 | `size/icon/sm` = 16 |
| `md` | 36 | `size/icon/md` = 20 |
| `lg` | 40 | `size/icon/md` = 20 |

Every action in the bar is an instance of this part. The tooltip is placed outside the button bounds so showing it never moves the bar.

## .Main/Video player actions bar

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `lg` |
| `Playing` | variant | `false, true` | `false` |
| `Show timestamps` | boolean | — | `true` |

Variants: 3 × 2 = **6**.

```text
.Main/Video player actions bar
layout: Vertical, Fill width, padding-top = fade zone, padding-x and padding-bottom per Size
fill: linear gradient color/overlay/scrim (bottom) → transparent (top)

└─ Content                       Horizontal, align Center, gap space/sm, Fill
   ├─ Play / pause               action, Type = Playing ? pause : play
   ├─ Volume                     .Main/Video player volume
   ├─ Video progress             Horizontal, align Center, gap space/md, Fill
   │  ├─ Timestamp start         "0:42", type/body/xs/medium, video-player/control/fg   Show timestamps
   │  ├─ Progress slider         Fill, height 4, radius/full, video-player/track
   │  │  ├─ Buffering progress   width = buffered %, video-player/track/buffer
   │  │  └─ Progress line        width = played %, color/fill/brand/solid
   │  └─ Timestamp end           "4:12"                                                 Show timestamps
   ├─ Playback speed             action, Type=playback-speed
   ├─ Captions                   action, Type=captions
   ├─ Cast                       action, Type=cast
   └─ Fullscreen                 action, Type=fullscreen
```

- **Video progress fills**; every action keeps its size.
- The top padding is the fade zone: it gives the gradient room so controls stay readable on bright video. It is part of the bar, not extra space under the video.

| Size | Fade zone | Padding x / bottom | Action size |
| --- | --- | --- | --- |
| `sm` | `space/3xl` = 24 | `space/md` = 8 | `sm` |
| `md` | `space/4xl` = 32 | `space/lg` = 12 | `md` |
| `lg` | `space/5xl` = 40 | `space/xl` = 16 | `lg` |

# 5. Video player

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `lg` |
| `Playing` | variant | `false, true` | `false` |
| `Show overlay action` | boolean | — | `true` |
| `Show actions bar` | boolean | — | `true` |

Variants: 3 × 2 = **6**.

```text
Video player
Fixed 16:9 frame, clip content, radius/surface

├─ Media                         Fill × Fill, image fill (the video frame; replace the fill to change the preview)
├─ Overlay action                .Main/Video player overlay action, absolute, centered   Show overlay action
└─ Actions bar                   .Main/Video player actions bar, absolute, bottom, Fill width   Show actions bar
```

| Size | Frame |
| --- | --- |
| `sm` | 480 × 270 |
| `md` | 720 × 405 |
| `lg` | 960 × 540 |

- The 16:9 media frame is the base. The overlay action and the actions bar are **absolutely positioned on top of it**; turning them on or off never changes the player's size.
- `Playing` switches the overlay icon and the play/pause action. It does not create a different anatomy.
- With `Playing=true` the overlay action is usually hidden; designers show it when mocking a hover.

## Token map

Media controls use component tokens that keep the same value in every color mode, because they sit on video rather than on the interface surface.

| Token | Value (every mode) | Used for |
| --- | --- | --- |
| `video-player/control/fg` | `color/text/on-solid` | icons, timestamps, progress handle |
| `video-player/action/fill/hover` | on-solid at 16% | action hover |
| `video-player/overlay/fill` | on-solid at 24% | overlay play button |
| `video-player/overlay/fill/hover` | on-solid at 32% | overlay play button hover |
| `video-player/tooltip/fill` | `color/overlay/scrim` | tooltip and timestamp indicator |
| `video-player/track` | on-solid at 24% | timeline and volume track |
| `video-player/track/buffer` | on-solid at 40% | buffered part of the timeline |
| Played progress | `color/fill/brand/solid` | progress line |
| Bar fade | `color/overlay/scrim` → transparent | actions bar gradient |

# 9. Guidelines

Topics in `4.2 Video player · Guidelines`, in order, each with a visual built from real instances:

1. **When to use.** A player in a course page and a static image in a marketing card. Caption: "Use the player when people will actually watch; use an image with a play link when video is secondary."
2. **Media, overlay, actions bar.** The player exploded into its three layers with callouts. Caption: "Controls overlay the media; the frame stays 16:9."
3. **Overlay, not layout.** Do: actions bar on top of the video. Don't: actions bar under the video, making the player taller than 16:9.
4. **The actions bar.** The `lg` bar with callouts on every action and the fade zone; a `Doc/Measure` on the timeline showing it fills.
5. **Playing and paused.** The same player in both states.
6. **Content.** Show realistic durations ("4:12"), a sensible playback speed ("1×") and a preview frame that represents the video, not a blank frame.
7. **Accessibility.**
   - Each player is a region with a unique accessible name, from its title ("Lesson 3: Variables") or an explicit label, so two players on one page can be told apart.
   - Every action has an accessible name ("Play", "Mute", "Enter full screen") and a tooltip with its shortcut: Space play/pause, M mute, F full screen, C captions, arrow keys seek and change volume.
   - Captions are available for speech; the captions action is always present when captions exist.
   - No autoplay with sound. Respect reduced motion: don't autoplay at all when the user has asked for reduced motion.
   - Focus rings on actions are visible on bright video (the focus effect plus the fade zone behind it).
8. **Do / don't** (`Doc/Do-dont` pairs):
   - Do keep controls on the media. Don't place them outside the frame.
   - Do use the action part. Don't redraw buttons inside the bar.
   - Don't autoplay with sound.
   - Do keep the fade zone. Don't put light controls straight on a bright frame.
9. **Maintenance.** Actions, tooltip, volume, bar and overlay are private parts here; change them once and every player updates. On-media colors live in the `video-player/*` tokens.

# 10. QA

Fail QA when:
- actions are drawn individually inside the actions bar instead of `.Main/Video player action` instances;
- volume or timeline controls do not reuse their parts;
- the actions bar pushes the video outside the 16:9 frame or adds height;
- `Playing` creates a separate player anatomy;
- overlay controls are not absolutely positioned overlays;
- media controls change color when the interface color mode changes;
- the examples in use are missing;
- a player region has no accessible name, or two players on one page share the same name.
