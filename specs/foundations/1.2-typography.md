# 1.2 Typography

The Typography page shows the typefaces, the full type scale with every weight it supports, and the variables and text styles behind it. Designers should be able to read the hierarchy from the specimen itself, not from token names.

Typography works in three layers:

```text
Primitives (scale/font-size/*, scale/line-height/*, scale/font-weight/*)
        ↓ aliases
Typography collection (font/*)       families, weights, sizes, line heights, letter spacing
        ↓ bound into
Text styles (type/{role}/{size}/{weight})
        ↓ applied by
Components
```

Components apply text styles. They never set font size, line height or weight by hand.

## .Main

- `.Main/Typography typeface card`: family name, a large `Aa` sample, the alphabet in upper and lower case, numerals `0–9`, and a punctuation line (`! ? & @ # % ( ) [ ] { } " ' , . : ; – —`). Every text layer uses a text style bound to the family it shows.
- `.Main/Typography weight cell`: one sample word in one style, with the weight name under it.

Type scale rows use `Doc/Type row` from `9.1 Doc kit`.

## · Overview

### 1. Typefaces

Block note: `Typefaces`. One `.Main/Typography typeface card` per family in use, in this order: `font/family/ui` (always), `font/family/display` (only when headings use a second family), `font/family/mono` (only when the product shows code or tabular data in a monospace face). The row note beside each card says what the family is used for.

### 2. Type scale

Block note: `Type scale`, badge `Text styles`. Every text style in the system, grouped by role, largest first. Each group starts with a `Doc/Row note` (role name and what it is for), then one `Doc/Type row` per role and size:

```text
Doc/Type row
├─ Style name      e.g. type/heading/lg
├─ Samples         one .Main/Typography weight cell per weight the role supports, side by side
└─ Metrics         size · line height · letter spacing · family
```

Text style names add the weight: `type/body/md/regular`, `type/heading/lg/semibold`, `type/body/sm/semibold`.

What each role is for:
- **Display**: hero and marketing headings. Created only when the product has marketing or editorial pages.
- **Heading**: page, section, card and dialog titles.
- **Body**: all running and interface text: paragraphs, descriptions, table cells, and the text inside controls (buttons, inputs, tabs, menu items, badges) and form labels. Weight separates the two uses: `regular` for reading text and input values, `medium` for labels, badges and menu items, `semibold` for buttons and links.
- **Code**: code, keys, IDs and tabular figures in the monospace family.

Rules:
- Never copy another system's scale into the brand. Take family, sizes, line heights, letter spacing and weights from the existing brand first. When they are missing, use the defaults above, adjusted for the product's density.
- The specimen shows every weight each role supports. A role with three weights shows three samples.
- Display and body roles are visibly separate groups.

## · Tokens

The `Typography` collection, one table per group, in this order. It has one mode, so each table has one value column (`Value`), whose chip shows the resolved value and the primitive it aliases.

| Group | Names | Usage copy covers |
| --- | --- | --- |
| Family | `font/family/ui`, `font/family/display`, `font/family/mono` | where each family is used |
| Weight | `font/weight/regular` (400), `medium` (500), `semibold` (600), `bold` (700) | which roles use each weight |
| Size | `font/size/{role}-{size}`, e.g. `font/size/body-md` | the style that uses it |
| Line height | `font/line-height/{role}-{size}`, e.g. `font/line-height/body-md` | the style that uses it |
| Letter spacing | `font/letter-spacing/display`, `heading`, `body`, `code` | the roles it tightens or keeps at 0 |
| Input minimum | `font/size/input-min` (16) | the smallest value text in a text control on mobile, so browsers don't zoom into a focused field |

Size and line height use the tree: one parent row per role (`font/size` · heading, value cell shows the range), each size is a child (`heading-xl`, `heading-lg`, … `heading-xs`) with `Doc/Tree connector`.

Example rows:

| Name | Value | Usage |
| --- | --- | --- |
| `font/family/ui` | the brand's UI typeface | Every interface role: headings, body, labels. |
| `font/weight/semibold` | `600` | Headings and emphasized labels such as button text. |
| `font/size/body-md` | `16` (`scale/font-size/16`) | Default paragraph and description text. |
| `font/line-height/body-md` | `24` (`scale/line-height/24`) | Line height of default paragraph text. |

## · Guidelines

Topics in this order. Each topic is heading → explanation → visual example → caption, built in the system's own typeface and text styles.

### 1. Establish a clear typographic hierarchy

Typography must set up five levels: display or hero text where needed, headings, body, labels and controls, and supporting or muted text. A designer must be able to read the hierarchy from the specimen without looking at the style names.

**Visual: complete type-scale specimen.** Every text style in the active typeface. For each: style name, sample text, size, line height, weight and letter spacing. Display and body roles are in clearly separate groups. (This is the type scale from Overview, set as a reading specimen with real sentences instead of single words.)

### 2. Display text vs body and UI text

Display styles are for large headings and high-emphasis text. Body styles are for paragraphs, form labels, navigation, buttons, menus and supporting content. Do not use display styles to create hierarchy inside dense UI; use weight, color role and spacing instead.

**Visual: three treatments of the same content.** A short paragraph set (1) in a suitable display treatment as a heading, (2) in a display style misused as body copy, and (3) in the correct body style. A callout on the second explains why it fails: oversized, too tight for reading, breaks the rhythm of the surrounding UI.

### 3. Base font size

Choose the base body size on purpose, based on the target devices, viewing distance, how legible the typeface is at small sizes, localization needs, accessibility and mobile input behavior. The default is 16, the size most products start from; a dense desktop tool can use 14. Text typed into inputs is at least 16 on iOS and mobile web, so the browser does not zoom when the field gets focus.

**Visual: base size comparison.** The same paragraph and the same compact control label at three sizes: a smaller candidate, the selected base size (marked `Selected`), and a larger candidate.

### 4. Line height

Tune line height per role. Body copy needs proportionally more line height than large display text. Defaults: body and code text from 1.4 to 1.5 × size, headings from 1.25 to 1.5 ×, display at 1.2 ×, every value on an even pixel. The exact default values are in the type scale table.

**Visual: line-height comparison.** The same paragraph three times, side by side: too tight, selected, too loose. Each is labeled with font size, line height and ratio (for example `16 / 24 · 1.5`).

### 5. Letter spacing

Large display text often needs tighter letter spacing; small body text stays at the typeface default. Defaults: display −2%, headings −1% from `heading/md` up, everything else 0.

**Visual: tracking comparison.** One large heading at default letter spacing, the selected letter spacing (marked `Selected`), and overly tight letter spacing. `Doc/Spec label` measurements show the gap between two letter pairs so the difference is visible.

### 6. Typeface suitability and weight coverage

When the brand already has a typeface, check that it supports the required scripts and languages, the weights the scale uses, the numerals and punctuation the product needs (tabular figures for tables, for example), readable small-size UI text, and display use if the system has display styles.

Never invent a weight the font does not have. When a role needs a weight that does not exist, map it to the nearest available weight and write that down.

**Visual: weight coverage.** The active family in every weight the system uses, each labeled with its `font/weight/*` variable and the roles that use it. A fallback mapping (for example "semibold → bold, the font has no 600") is shown with a callout.

### 7. Keep the number of families intentional

One strong family is usually enough. Add a second family only for a clear reason: display or editorial contrast, code and monospace content, or a script the main family does not cover. Fewer families load faster, pair more predictably and are easier to maintain.

**Visual: family roles.** Only when the system uses more than one family: family A with its role, family B with its role, and one composed screen (for example an article header over a settings form, or a docs page with a code block) showing how they work together. A single-family system skips this visual and does not invent a second family to fill it.

### 8. Change typography from the source

Typography changes start at the source and flow outward: primitives and `font/*` variables → `type/*` text styles → components. Document the actual architecture of this system: the variables, the text styles, the role names and which components use them.

**Visual: three workflow steps**, built from this file:
1. **Text style overview**: the style list grouped by role (display, heading, body, code).
2. **Typography collection**: the `Typography` collection open on `font/size/*` and `font/line-height/*`.
3. **Edit and propagate**: one source value changed (for example `font/size/body-md` from 16 to 15), then the dependent text styles and a text field, a menu item and a table row updated.

### 9. Text size in apps (App products only)

On iOS and Android, people choose their own text size, and the apps follow it. The text styles stay the same; every one of them grows and shrinks with that setting. Layouts make room for larger text: they wrap, grow or scroll, and never cut text off. A control's height is a minimum, so it grows with its label. Skip this topic when the product is Web only (`specs/SYSTEM.md` Part A §A5).

**Visual: one screen at three text sizes.** The same phone screen area (a heading, a paragraph, a text field and a `md` button) at the default text size, at a large size and at the largest accessibility size. It shows the text wrapping and the button growing taller instead of clipping.

### Not included

These do not help build or maintain the type system and are not generated: catalogs of free or paid fonts, pricing, marketplace or type-discovery screenshots, and recommendations unrelated to the brand's own typeface.

# 2. QA

- The Overview shows a typeface card for every family in use and a type-scale row for every text style.
- Every role shows a sample for each weight it supports.
- Every text style binds family, size, line height, letter spacing and weight to `font/*` variables.
- Text style names follow `type/{role}/{size}/{weight}`.
- The Tokens tables show size and line height as role trees with connectors.
- Guidelines fail QA when a topic is text only, line-height guidance has no side-by-side comparison, letter-spacing guidance has no comparison while display text exists, weight coverage is not shown, or the workflow uses names that are not this system's style and variable names.
