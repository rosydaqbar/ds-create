# 4.1 Rich text editor

A Rich text editor lets people write formatted text — bold, lists, links, images — without writing markup. It combines a **toolbar** of formatting commands with an **editing surface**, and can show the commands in a **floating toolbar** next to selected text instead.

Use it for comments, descriptions, messages and notes where formatting helps the reader. Use a Textarea field (3.2) when plain text is enough; most fields are.

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Type` | variant | `simple, advanced` | `advanced` |
| `Show selects` | boolean | — | `true` (advanced only) |

Variants: **2**.

```text
Rich text toolbar
layout: Horizontal, align Center, gap space/md, Hug

├─ Selects                       Horizontal, gap space/md                 advanced, Show selects
│  ├─ Select                     3.5, Size=sm, "Normal text"
│  └─ Select                     3.5, Size=sm, "Medium"
└─ Commands                      Horizontal, align Center, gap space/xxs
   ├─ command bold
   ├─ command italic
   ├─ command underline
   ├─ Divider wrapper            Horizontal, padding-x space/xs, height 20
   │  └─ Divider                 2.16, Orientation=vertical
   ├─ command color                                                       advanced
   ├─ Divider wrapper                                                     advanced
   ├─ command bullet-list
   ├─ command align-left / align-center / align-right                    (simple: align-left only)
   ├─ Divider wrapper
   ├─ command link
   ├─ command image
   ├─ Divider wrapper                                                     advanced
   ├─ command generate                                                    advanced
   └─ command more                                                        advanced
```

- Dividers live inside `Divider wrapper` frames so the spacing around every divider is the same. Never place a loose line between commands.
- Group order: text style → colour → paragraph → insert → AI and more.

| --- | --- | --- | --- |

It appears above the selection (or below it near the top of the viewport) and never covers the selected text.

# 7. Rich text editor

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm, md` | `md` |
| `Type` | variant | `default, floating-toolbar` | `default` |
| `Show scroll bar` | boolean | — | `false` |
| `Show hint` | boolean | — | `true` |

Variants: 2 × 2 = **4**.

```text
Rich text editor
layout: Vertical, gap per Size, width 640 in the set (Fill in layouts), Hug height

├─ Rich text toolbar             instance, Type=advanced              Type=default
└─ Input and hint                Vertical, gap space/sm, Fill
   ├─ Input                      Vertical, Fill width, min height per Size, padding per Size
   │  │                          same fill, border, radius and focus as the Text control (2.10)
   │  ├─ Rich text content       Vertical, gap space/md, Fill, top-aligned
   │  │  ├─ Heading              type/heading/xs/semibold
   │  │  ├─ Paragraph            type/body/{sm|md}/regular
   │  │  └─ List                 type/body/{sm|md}/regular, bullets
   │  ├─ Resize handle           bottom trailing corner, absolute
   │  └─ Scroll bar              .Main/Rich text editor scroll bar, absolute, trailing edge   Show scroll bar
   └─ Help text                  instance 2.12                        Show hint
```

- With `Type=floating-toolbar`, the fixed toolbar is removed and formatting is reached through the floating toolbar on selection. The content model is the same.
- The `Input` is a frame, not a Text control instance, because rich content (headings, lists, links) cannot sit inside an instance. It binds **the same tokens as the Text control**, so a change to fields reaches the editor too.
- The hint sits **below** the surface, never inside it. Resize handle and scroll bar are their own layers, never part of the content.
- Content is top-aligned and scrolls inside the surface when it is longer than the current height.

| Size | Gap toolbar → input | Input padding | Min height | Content style |
| --- | --- | --- | --- | --- |
| `sm` | `space/md` = 8 | `space/lg` = 12 × `space/xl` = 16 | 120 | `type/body/sm/regular` |
| `md` | `space/lg` = 12 | `space/xl` = 16 × `space/2xl` = 20 | 160 | `type/body/md/regular` |

# 9. Guidelines

Topics in `4.1 Rich text editor · Guidelines`, in order, each with a visual built from real instances:

1. **Editor or textarea.** A Textarea field (3.2) and a Rich text editor side by side for the same task. Caption: "Choose the editor only when formatting helps the reader."
2. **Editor anatomy.** The editor with callouts: toolbar → command → divider wrapper → input → content → resize handle → hint.
3. **Simple or advanced.** Both toolbars above the same surface. Caption: "Start simple; add advanced commands only where people format long content."
4. **Command states.** One command in rest, hover, selected and selected + hover. Caption: "Selected shows the format at the cursor; it is not hover."
5. **Floating toolbar.** The text-highlight example with a callout: "The same commands, next to the selection. It never covers the selected text."
6. **Content, scroll and resize.** A short and a long editor; the long one with the scroll bar and resize handle called out.
7. **Content.** Keep the number of formatting options small; offer what the output can render. Placeholder text describes what to write ("Write a description…"); hints carry limits ("Up to 2,000 characters"). Sample and example content never skips heading levels: each heading is at most one level below the heading before it (an H2 is followed by an H3, never an H4).
8. **Accessibility.**
   - The toolbar is one tab stop; arrow keys move between commands.
   - Every command has an accessible name and shows a Tooltip (2.13) with its name and shortcut (Kbd 2.17): "Bold ⌘B".
   - Selected commands announce their pressed state.
   - Every command in the floating toolbar is also reachable from the keyboard (shortcuts or the fixed toolbar); essential actions are never only in floating UI.
   - The input has a label (a Label (2.11) above it, or an accessible name).
9. **Do / don't** (`Doc/Do-dont` pairs):
   - Do use the command part. Don't draw toolbar icons by hand.
   - Do keep dividers in wrappers. Don't place lines with uneven gaps.
   - Do offer a focused set of commands. Don't show every formatting option in a comment box.
   - Don't hide essential actions (submit, attach) only in the floating toolbar.
10. **Maintenance.** Commands change in `.Main/Rich text editor command` and update both toolbars; the surface follows the Text control tokens; selects follow Select (3.5).

# 10. QA

Fail QA when:
- toolbar commands are hand-drawn icons instead of `.Main/Rich text editor command` instances;
- the `Selected` state is missing;
- dividers are loose lines or have uneven spacing instead of `Divider wrapper` + Divider (2.16);
- the floating toolbar uses a different command system;
- resize handle, scroll bar or hint are flattened into the rich content;
- content is vertically centred in the input;
- the input uses different tokens from the Text control;
- the examples in use (comment box, text highlight) are missing;
- sample or example content skips a heading level.
