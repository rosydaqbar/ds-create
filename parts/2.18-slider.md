# 2.18 Slider

Sliders let users select one value, or a range between two values, by dragging a handle along a track. They are useful for dynamic filtering (price, distance, date ranges) and for settings where the position matters more than the exact number (volume, opacity).

The Slider is built from a background track, a progress line between the two values, and two instances of one reusable handle. Every value combination uses the same parts; nothing is drawn per value.

Use a Text control (2.10) when users need an exact value, and Radios (2.8) or a segmented Button group (3.1) when there are only a few named choices.

# 1. Purpose

- Pick a value or a range on a continuous or stepped scale.
- Filter content live as the handle moves.
- Show the chosen value(s) clearly without moving the handle when the label appears.

# 4. Property inventory

## Slider

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Start value` | variant | `0`, `25`, `50`, `75` | `0` |
| `End value` | variant | `25`, `50`, `75`, `100` | `50` |
| `Placement` | variant | `none`, `bottom`, `top` | `none` |
| `Show start handle` | boolean | — | true |

Variants: every combination where `Start value` is lower than `End value` (10 pairs) × `Placement` 3 = 30, e.g. `Start value=25, End value=75, Placement=bottom`.

- `Start value` and `End value` name the two ends of the progress line. They follow the `{Part} icon` pattern of the property vocabulary for a value that belongs to one part.
- A single-value slider is `Start value=0` with `Show start handle` off.
- `Placement` is where the value labels sit: `none` (no labels), `bottom` (text under each handle), `top` (a Tooltip floating above the active handle).
- The handle instances expose their `State` property on the Slider instance, so designers can set `hover` or `focus` on either handle from the Slider.
- Any value between the steps is set on the instance: move the handle and resize the Progress so its edges sit at the two knob centres, and change the label text. Never draw a new shape.

# 5. Anatomy

## Slider

```text
Slider
layout: Vertical
width: 320 in the set; Fill in layouts
height: Hug

├─ Label space                        top only; height = Tooltip height + space/md
├─ Track area
│  layout: none (positioned)
│  height: handle size (24)
│  padding: handle size / 2 on the start and end, so handles at 0 and 100 stay inside the bounds
│  ├─ Background track                Fill width; height size/track/lg; centred vertically; radius/full
│  └─ Progress                        x = Start value %, width = (End value − Start value) % of the track
│     ├─ Progress line                Fill the Progress; same height as the track; radius/full
│     ├─ Start handle                 .Main/Slider handle; knob centre on the Progress start edge
│     └─ End handle                   .Main/Slider handle; knob centre on the Progress end edge
└─ Label space                        bottom only; height = label line height + space/md
```

The Progress spans from the Start value to the End value. Both handles live inside it, pinned to its start and end edges, so moving or resizing the Progress always keeps the line starting and ending at the handles.

## .Main/Slider handle

```text
.Main/Slider handle
layout: none (positioned)
size: knob only (24 × 24)
clip content: off

├─ Knob                               circle 24; fill, border, elevation by State
├─ Text                               bottom only; centred under the knob, space/md below it
└─ Tooltip                            top only; Tooltip instance, Placement=top, centred above the knob, space/md above it
```

The handle's bounds are the knob. Text and Tooltip are positioned outside the bounds, so turning a label on or off never moves the knob, and the knob centre stays on the logical value.

## Auto Layout relationship

- The Slider root stacks `Label space` (top), `Track area` and `Label space` (bottom) vertically. Label spaces are reserved room, so the track sits at the same y in every value of a Placement, and labels never overlap content around the Slider.
- `Track area` is a positioned frame: the track fills it; the Progress is positioned by value.
- The handle is a positioned composition with its labels outside its bounds.

# 7. States

States live on the handle:

| State | Knob fill | Knob border | Ring |
| --- | --- | --- | --- |
| `rest` | `color/surface/base` | `color/border/brand` | — |
| `hover` | `color/fill/brand/subtle` | `color/border/brand` | — |
| `focus` | `color/surface/base` | `color/border/brand` | `focus/default` |

`focus` is visibly different from `hover`: it adds the focus ring around the knob. In the product, the focused handle shows its Tooltip when `Placement=top`.

# 10. Guidelines content

Topics for `2.18 Slider · Guidelines`, in order. Each visual uses real Slider instances.

## When a Slider is right

Use a Slider when the position on a scale matters more than the exact number, and when seeing the effect live helps (filters, volume, opacity). When users need an exact value, pair the Slider with Text controls or use a Text control alone. When there are only a few named choices ("Small, Medium, Large"), use Radios or a segmented Button group: a discrete control is clearer.

Visual — Do/don't pair (`Doc/Do-dont`):
- Don't: a Slider with three steps labelled "S", "M", "L".
- Do: a segmented Button group "Small · Medium · Large".

## Single value or range

Use a single-value slider for one setting. Use a range to filter between a minimum and a maximum; the handles never cross, and the progress line always runs between them.

Visual — the volume setting and the price filter from the Overview side by side.

## Anatomy: track, progress, handles

The background track shows the full scale; the progress line shows the selected part; each end is the same reusable handle. Edit the handle part once to change every Slider.

Visual — propagation example: (1) `.Main/Slider handle` with its Knob border highlighted, (2) the dependency arrow to `Slider`, (3) three Slider instances showing the updated knob.

## Labels

- `none` when the value is shown elsewhere (in Text controls next to the Slider) or doesn't matter (volume).
- `bottom` for a permanent readout under each handle.
- `top` for a value that floats above the handle while it is dragged or focused.

Labels never move the handle: the knob centre stays on the value, whatever the label.

Visual — the three placements stacked with a dashed guide through the knob centres; then a Don't version where the label pushes the knob off its value.

## Min, max and units

Always show what the ends mean — minimum and maximum, or icons for low and high — and the unit of the value, either in the labels ("$200") or in the field label ("Price, $").

Visual — Don't: an unlabelled range with no ends. Do: the price filter with "$0" and "$1,000" at the ends and "$200"–"$600" on the handles.

## Not for measurements

A Slider is for values users set. Don't use it to display a level users can't change, such as signal strength or a progress amount; use Progress (2.14) or a dedicated indicator.

Visual — Don't: a disabled Slider showing battery level. Do: a Progress bar "Battery 60%".

## Interaction

- Dragging the knob moves it; clicking the track moves the nearest handle to that point.
- Arrow keys move the focused handle by one step; Page Up and Page Down by a larger step; Home and End to the minimum and maximum.
- In a range, the start handle can't pass the end handle and vice versa.
- The hit area of each knob extends to `size/touch-min` on touch screens without changing its visual size.

Visual — a knob with its 24 visual size and the larger touch hit area drawn dashed around it.

## Content

- Value labels show the number with its unit when the unit isn't stated nearby ("40%", "25 km").
- Keep labels short enough not to overlap when the two handles are close; shorten units ("k" for thousands) before dropping them.

## Accessibility

- Each handle is a separate slider control with its minimum, maximum and current value. When the shown value is formatted (a unit, a currency, "k" for thousands), the handle also has a human-readable value text ("$200", "25 km"), so it is announced the way it reads.
- Every handle has an accessible name: from the visible Label, or set explicitly when there is none (a volume slider named "Volume").
- In a range, each handle has its own name, "{name} minimum" and "{name} maximum" ("Price minimum", "Price maximum"), so the two handles can be told apart.
- Focus is always visible: the focus ring sits around the focused knob.
- The progress line meets the non-text contrast threshold against the track, and the knob border against the surface, in every colour mode.

# 11. QA

Fail QA when:
- the range ends are not instances of `.Main/Slider handle`;
- values are drawn as unrelated shapes instead of one Progress positioned and sized by value;
- the progress line doesn't start and end at the knob centres;
- turning on a label (`bottom` or `top`) moves the knob or changes the track's position;
- the `focus` state is missing or looks the same as `hover`;
- handles at 0 or 100 stick out of the Slider's bounds;
- the top label is a custom bubble instead of a Tooltip instance;
- colours, sizes and radius are raw values instead of the tokens in §9;
- a handle has no accessible name, the two handles of a range share one name, or a formatted value has no value text.
