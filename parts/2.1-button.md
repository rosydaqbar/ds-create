# 2. Published set and properties

Published set: `Button`

Variant name pattern: `Size=md, Emphasis=primary, Tone=brand, State=rest, Icon only=false`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `xs, sm, md, lg, xl` | `md` | height, padding, gap, label style |
| `Emphasis` | variant | `primary, secondary, tertiary` | `primary` | container treatment: solid fill, bordered surface, or no container |
| `Tone` | variant | `brand, danger` | `brand` | semantic intent; `danger` for destructive actions |
| `State` | variant | `rest, hover, pressed, focus, disabled, loading` | `rest` | interaction treatment |
| `Icon only` | variant | `false, true` | `false` | square form with one centred icon and no label |
| `Label` | text | — | "Button" | the visible label |
| `Show leading icon` | boolean | — | `false` | shows `Leading icon` |
| `Show trailing icon` | boolean | — | `false` | shows `Trailing icon` |
| `Leading icon` | instance swap | icons | `plus` | glyph in the leading slot (and the only glyph when `Icon only=true`) |
| `Trailing icon` | instance swap | icons | `arrow-right` | glyph in the trailing slot |
| `Show loading text` | boolean | — | `true` | in `State=loading`: true shows Spinner + label, false shows the Spinner alone |

Variant count: 5 sizes × 3 emphasis × 2 tones × 6 states × 2 icon-only = **360 variants**.

Rules:
- Do not invent extra emphasis levels to produce variety. Three levels are the system.
- Danger is a `Tone` value in the same set. Never build a separate destructive set.
- Loading is a `State` value. Never build a separate loading button.

# 3. Anatomy

Text button:

```text
Button
layout: Horizontal
align: Center / Center
padding: button/padding-x/{Size} left and right, 0 top and bottom
height: size/control/{Size} (Fixed)
width: Hug

├─ Leading icon                         optional icon instance (Show leading icon); replaced by Spinner when State=loading
├─ Text padding
│  layout: Horizontal
│  padding: space/optical left and right
│  ├─ Label                             text, Hug, single line
└─ Trailing icon                        optional icon instance (Show trailing icon)
```

Icon-only button (`Icon only=true`):

```text
Button
layout: Horizontal
align: Center / Center
width = height = size/control/{Size} (Fixed, square)

└─ Leading icon                         the only child; replaced by Spinner when State=loading
```

Loading (`State=loading`):

```text
Button
├─ Spinner                              instance of 2.15 Spinner, in the Leading icon position, same box as the icon
├─ Text padding                         visible when Show loading text = true
│  └─ Label                             loading phrase, for example "Saving…"
└─ Trailing icon                        hidden
```

## The Text padding wrapper is mandatory

The label is always wrapped in a small horizontal Auto Layout frame named **Text padding**. Do not replace it with a bare text layer.

Why: icon glyphs carry invisible live-area padding inside their frame. Placed next to a bare label, an icon frame makes the button look heavier on the icon side. The Text padding wrapper adds a small optical inset (`space/optical`, 2 by default) on both sides of the label, and the button's outer padding is reduced by the same amount. The result: label-only, leading-icon, trailing-icon and both-icon buttons all read as visually centred, and the label sits at the same position whether icons are on or off.

## Auto Layout relationship

| Node | Direction | Width | Height | Padding | Gap |
| --- | --- | --- | --- | --- | --- |
| `Button` | Horizontal, centred | Hug | Fixed `size/control/{Size}` | `button/padding-x/{Size}` left/right | `button/gap/{Size}` |
| `Leading icon` | — | Fixed `size/icon/md` | Fixed `size/icon/md` | — | — |
| `Text padding` | Horizontal | Hug | Hug | `space/optical` left/right | — |
| `Label` | — | Hug | Hug | — | — |
| `Trailing icon` | — | Fixed `size/icon/md` | Fixed `size/icon/md` | — | — |
| `Spinner` | — | Fixed, same box as the icon | Fixed | — | — |

Flexible vs fixed children:
- `Label` (inside `Text padding`) grows with the text; the button width hugs it.
- Icons and Spinner are fixed boxes.
- Height is fixed per size; long labels never wrap. When a layout gives the button a fixed or Fill width (full-width mobile buttons), the content stays centred.

# 4. Sizes and measurements

Defaults (the brand can change values; relationships stay):

| Size | Height | Padding-x | Gap | Icon | Label style | Icon-only side |
| --- | --- | --- | --- | --- | --- | --- |
| `xs` | `size/control/xs` = 32 | `button/padding-x/xs` = 10 | `space/xs` = 4 | `size/icon/md` = 20 | `type/body/sm/semibold` | 32 |
| `sm` | `size/control/sm` = 36 | `button/padding-x/sm` = 12 | `space/xs` = 4 | `size/icon/md` = 20 | `type/body/sm/semibold` | 36 |
| `md` | `size/control/md` = 40 | `button/padding-x/md` = 14 | `space/xs` = 4 | `size/icon/md` = 20 | `type/body/sm/semibold` | 40 |
| `lg` | `size/control/lg` = 44 | `button/padding-x/lg` = 16 | `space/sm` = 6 | `size/icon/md` = 20 | `type/body/md/semibold` | 44 |
| `xl` | `size/control/xl` = 48 | `button/padding-x/xl` = 18 | `space/sm` = 6 | `size/icon/md` = 20 | `type/body/md/semibold` | 48 |

- The md baseline: height 40, padding-x 14, gap 4, icons 20, Text padding inset 2 on each side, so the label sits 16 from the edge on a label-only button.
- `button/padding-x/{Size}` is a component token: the visual padding minus `space/optical`.
- Icon-only buttons are square: side = the size's control height, icon centred, no padding tokens needed.
- On touch platforms, `xs` and `sm` reach `size/touch-min` through hit-area padding in code; the visual size does not change.

# 5. States

| State | What changes |
| --- | --- |
| `rest` | base tokens |
| `hover` | fill (and text for secondary/tertiary) moves to its `hover` child token |
| `pressed` | fill moves to its `pressed` child token |
| `focus` | rest tokens + focus ring effect (`focus/default` for brand, `focus/danger` for danger) |
| `disabled` | disabled fill, border and text; icons follow the text colour; no effects |
| `loading` | rest tokens; the leading slot shows Spinner; trailing icon hidden; not clickable |

Rules:
- Focus uses the focus-ring effect and must stay visibly distinct from hover.
- The focus ring is a drop shadow with spread. In Figma it renders only on a frame with clip content on and a fill bound to a variable; tertiary buttons keep a `color/fill/none` fill for this reason.
- Loading keeps the button's identity (emphasis, tone, size). It hides or changes the visible label through `Show loading text`; it never becomes a separate component.
- Disabled keeps the label legible enough to identify the action.

# 7. Token map

Colour roles per emphasis and tone. Hover and pressed are children of the rest token.

**Tone=brand**

| Part | primary | secondary | tertiary |
| --- | --- | --- | --- |
| Root fill | `color/fill/brand/solid` → `/hover`, `/pressed` | `color/surface/base` → `/hover`, `/pressed` | `color/fill/none`; hover `color/fill/neutral/subtle/hover`, pressed `color/fill/neutral/subtle/pressed` |
| Root border | none | `color/border/default` | none |
| Label, icons | `color/text/on-solid`, `color/icon/on-solid` | `color/text/secondary`; hover and pressed `color/text/primary` | `color/text/secondary`; hover and pressed `color/text/primary` |
| Focus effect | `focus/default` | `focus/default` | `focus/default` |

For the brand tone, secondary and tertiary are neutral so the brand colour stays reserved for the one primary action.

**Tone=danger**

| Part | primary | secondary | tertiary |
| --- | --- | --- | --- |
| Root fill | `color/fill/danger/solid` → `/hover`, `/pressed` | `color/surface/base`; hover `color/fill/danger/subtle/hover`, pressed `color/fill/danger/subtle/pressed` | `color/fill/none`; hover `color/fill/danger/subtle/hover`, pressed `color/fill/danger/subtle/pressed` |
| Root border | none | `color/border/danger/subtle` | none |
| Label, icons | `color/text/on-solid`, `color/icon/on-solid` | `color/text/danger` → `/hover` | `color/text/danger` → `/hover` |
| Focus effect | `focus/danger` | `focus/danger` | `focus/danger` |

**Disabled (all emphasis, both tones)**

| Part | primary | secondary | tertiary |
| --- | --- | --- | --- |
| Root fill | `color/fill/neutral/subtle/disabled` | `color/surface/base` | `color/fill/none` |
| Root border | `color/border/disabled` | `color/border/disabled` | none |
| Label, icons | `color/text/disabled` | `color/text/disabled` | `color/text/disabled` |

**Shape, size and effects**

| Part | Token |
| --- | --- |
| Root radius | `radius/control` |
| Root border width | `border/width/default` |
| Root height | `size/control/{Size}` |
| Root padding-x | `button/padding-x/{Size}` |
| Gap | `button/gap/{Size}` (aliases `space/xs` or `space/sm`) |
| Text padding inset | `space/optical` |
| Icon box | `size/icon/md` |
| Depth (only when the brand uses depth) | `elevation/control` on primary and secondary rest, hover and pressed |

When the brand uses a depth treatment, the whole effect stack lives in effect styles (`elevation/control`, `focus/default`, `focus/danger`) so it can be changed or removed in one place.

# 8. Guidelines

`2.1 Button · Guidelines` is a dedicated reading-oriented frame and is required. Topics, in order, each with the visual teaching module in §9:

## 8.1 Buttons should look actionable
Explain why buttons need clear affordance, and how container, border, depth, contrast and interaction states communicate that something can be clicked. Module §9.1.

## 8.2 Emphasis
Explain why several action levels are needed and how primary, secondary and tertiary create a clear priority. One primary action per view or dialog. Module §9.2.

## 8.3 Danger tone
Explain:
- not every negative or cancel action needs the danger tone;
- a lower-emphasis secondary action is often enough;
- use `Tone=danger` when the destructive action itself is the primary consequential action (delete, remove, revoke).

Module §9.3.

## 8.4 Optically balancing buttons
This section is mandatory because it directly explains the button anatomy.

Document:
- icon libraries use consistent outer frames (live areas);
- glyphs contain internal optical padding;
- using raw icon-frame dimensions next to text makes the button look unbalanced;
- the label is wrapped in a small horizontal Auto Layout **Text padding** frame;
- the button's outer horizontal padding is reduced by the same amount;
- this keeps label-only and icon + label buttons visually centred.

Modules §9.4–§9.7.

## 8.5 Depth and effect treatment
Only when the brand uses depth. Explain:
- subtle depth comes from effect styles;
- it must stay accessible (contrast and focus visibility unchanged);
- effects are centralised so they can be changed or removed globally.

Modules §9.8–§9.10.

## 8.6 Content
- Labels are verbs or verb + noun ("Save changes", "Delete project"), never "OK" or "Click here" on their own.
- Use the brand's case rule (sentence case by default); keep labels to three words where possible.
- Loading labels say what is happening ("Saving…"), not "Loading…".
- Icon-only buttons need an accessible name in code and a Tooltip (2.13) on hover.

## 8.7 Accessibility
- Every state meets text contrast against its fill; disabled is exempt but stays legible.
- Focus is always visible and never removed; it differs from hover.
- Loading announces the progress phrase; the button is not clickable while loading.
- Prefer explaining why an action is unavailable over a silent disabled button.

## 8.8 Do / don't
Built from real instances, each with `Doc/Do-dont`:
- Do: one primary per view. Don't: three primary buttons side by side.
- Do: danger tone on "Delete project". Don't: danger tone on "Cancel".
- Do: icon + label with Text padding. Don't: icon placed against a bare text layer.
- Do: loading in place. Don't: replace the button with a separate spinner.

The documentation describes the active generated system, not another product or source library.

# 9. Visual teaching modules

Long-form Button documentation is not complete without the visual comparisons that explain the design decisions. All visuals use real `Button` instances and the generated icon family.

## 9.1 Buttons should look actionable

Create two versions of the same action context.

**Example A — clear affordance**
- a real Button instance;
- visible emphasis and state;
- obvious click target.

**Example B — too visually ambiguous**
- remove enough container, border and depth cues that the control starts to look like static text.

Keep the label, placement and surrounding content the same. The comparison demonstrates affordance rather than labelling one "good" and one "bad".

## 9.2 Emphasis

Create a realistic action group showing primary, secondary and tertiary (and a 2.3 Link where the layout needs a quiet navigation action).

Then create a second version where every action has equal emphasis. Content and number of actions stay identical.

Annotate:
- which action should be noticed first;
- why equal-emphasis actions increase scanning and decision effort.

## 9.3 Danger-tone comparisons

Use a dialog scenario. Create three examples:

1. **Overly aggressive** — a cancel-like action uses `Tone=danger` unnecessarily.
2. **Neutral alternative** — `secondary` or `tertiary` where the action is not itself destructive.
3. **True destructive primary action** — deletion, removal or another irreversible action uses `Emphasis=primary, Tone=danger`.

When no dialog component is in scope, build a documentation-only composition from surface, text and Button instances rather than introducing a new published component.

## 9.4 Icon live area

Create an annotated diagram showing:
- the icon component frame;
- the visible glyph bounds;
- the invisible live-area space;
- the label baseline;
- the perceived gap when a raw icon frame sits beside text.

Use the generated icon family.

## 9.5 The icon-padding problem

Create a button with a leading icon, a bare text layer and mathematically equal outer padding. Annotate why it looks optically unbalanced.

Show `Doc/Measure` guides for:
- outer padding;
- icon frame;
- visible glyph;
- gap to text.

## 9.6 Padding accumulation

Create a diagram that breaks down the total perceived left and right spacing in an icon + label button:
- root padding;
- icon live area;
- explicit gap;
- label bounds.

The point: the same numeric outer padding on both sides can still feel wrong.

## 9.7 Corrected Text padding anatomy

Show the corrected construction:

```text
Button
├─ Leading icon
├─ Text padding
│  ├─ optical inset
│  ├─ Label
│  └─ optical inset
└─ Trailing icon
```

Place four buttons side by side — label only; leading icon + label; label + trailing icon; both icons — and verify their labels appear optically centred. This is a core anatomy explanation, not decoration.

## 9.8 Depth treatment

Only when the brand uses depth (elevation is not flat). Show:
- a flat button;
- the depth treatment;
- an effect-stack annotation.

Do not show a tactile or skeuomorphic style when the brand direction is flat.

## 9.9 Effect-stack anatomy

When effects are used, create a zoomed visual showing:
- border;
- outer shadow;
- inner highlight where applicable;
- focus ring;
- the effect style name of each layer.

## 9.10 Changing effects globally

Create a before/after editor workflow:
- the shared effect style selected;
- the effect turned off or changed;
- primary, secondary and tertiary buttons updating together.

The example demonstrates centralised maintenance.

# 10. QA

Fail QA when:
- the `Text padding` wrapper is missing;
- icons are placed directly against a bare text layer;
- icon-only buttons use dimensions unrelated to the size's control height;
- loading is a separate component, or does not instance Spinner (2.15);
- danger buttons use a different set or different anatomy from brand buttons;
- the full 360-variant matrix is absent or reduced to samples;
- properties use names outside the vocabulary (`Hierarchy`, `Destructive`, `Default`, `Focused`);
- focus looks the same as hover, or the focus ring does not render on tertiary;
- the depth treatment cannot be changed centrally through effect styles;
- Guidelines are prose-only;
- the actionable vs ambiguous comparison, emphasis comparison or danger-tone comparison is missing;
- the icon live-area diagram, incorrect-padding and corrected-padding examples are missing;
- the Text padding wrapper is not shown visually;
- depth examples appear when the brand direction is flat;
- documentation visuals use a different anatomy from the published Button.
