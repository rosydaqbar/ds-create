# 2.13 Tooltip

Tooltips describe or identify interface elements, especially icons or images whose meaning is not obvious from the visible UI alone. A Tooltip is a small surface with a short text, an optional supporting line and an arrow pointing at its trigger.

The page holds two published sets:
- **Tooltip** — the surface, text and arrow;
- **Help icon** — a help-circle icon that opens a Tooltip. Label (2.11) instances it as its help icon.

Help icon composes the Tooltip family rather than duplicating its text and surface anatomy, so a change to the Tooltip propagates to every help icon in every field.

# 1. Purpose

- Name icon-only controls (an Icon button, 2.2) and identify images.
- Add short, non-essential detail on hover or focus.
- Provide one consistent help trigger for fields.

# 4. Property inventory

## Tooltip

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Placement` | variant | `none`, `top`, `top-start`, `top-end`, `bottom`, `left`, `right` | `top` |
| `Text` | text | — | "This is a tooltip" |
| `Show supporting text` | boolean | — | false |
| `Supporting text` | text | — | "Tooltips are used to describe or identify an element. In most scenarios, tooltips help the user understand meaning, function or alt-text." |

Variants: `Placement` 7 = 7, e.g. `Placement=top-start`.

`Placement` names where the Tooltip sits relative to its trigger. The arrow is on the opposite edge:

| Placement | Tooltip sits | Arrow on | Arrow aligned |
| --- | --- | --- | --- |
| `none` | anywhere (follows the pointer) | — (no arrow) | — |
| `top` | above the trigger | bottom edge | centre |
| `top-start` | above, extending to the end | bottom edge | start |
| `top-end` | above, extending to the start | bottom edge | end |
| `bottom` | below the trigger | top edge | centre |
| `left` | left of the trigger | right edge | centre |
| `right` | right of the trigger | left edge | centre |

## Help icon

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `State` | variant | `rest`, `hover`, `focus` | `rest` |
| `Placement` | variant | same seven values as Tooltip | `top` |
| `Show supporting text` | boolean | — | false |
| `Show cursor` | boolean | — | false |

Variants: `State` 3 × `Placement` 7 = 21, e.g. `State=hover, Placement=right`. `rest` exists for every placement so switching state keeps the chosen placement.

- `rest` — icon only; the tooltip is hidden.
- `hover` — the tooltip is open and the cursor specimen can be shown.
- `focus` — the tooltip is open and the icon has the focus ring.

`Show cursor` is a documentation specimen for mockups; it has effect only in `State=hover`.

In the Help icon, `Placement=none` places the tooltip above the icon without an arrow.

# 5. Anatomy

## Tooltip

```text
Tooltip
layout: Vertical (top-*, bottom) / Horizontal (left, right)
gap: 0
width: Hug
height: Hug

├─ Arrow row                          only for bottom (first) and right (first)
│  └─ Arrow                           .Main/Tooltip arrow
├─ Content
│  layout: Vertical
│  padding: space/md (8) × space/lg (12); space/lg (12) on all sides with supporting text
│  max width: size/width/xxs
│  radius: radius/surface
│  fill: color/surface/inverse
│  effect: elevation/overlay
│  └─ Text and supporting text
│     layout: Vertical
│     gap: space/xs
│     ├─ Text
│     └─ Supporting text              optional (Show supporting text)
└─ Arrow row                          only for top, top-start, top-end (last) and left (last)
   layout: Horizontal (Vertical for left/right)
   padding: space/lg on the start and end
   align: start / centre / end by Placement
   └─ Arrow                           .Main/Tooltip arrow
```

The arrow is a sibling of the Content in the same Auto Layout, never drawn into the Content surface. Order and alignment of the `Arrow row` are what the `Placement` variants change; the Content is the same in every variant. `Placement=none` has no Arrow row.

## .Main/Tooltip arrow

```text
.Main/Tooltip arrow
frame: 16 × 6 (6 × 16 for left/right), no fill
└─ Shape                              triangle pointing away from the Content; fill color/surface/inverse
```

The arrow's fill is the same variable as the Content fill, so the two always read as one surface.

## Help icon

```text
Help icon
layout: none (positioned composition)
size: size/icon/sm (16 × 16)
clip content: off

├─ Icon                               help-circle, 16 × 16
├─ Tooltip                            instance of Tooltip; hover/focus only; positioned outside the bounds
└─ Cursor                             pointer cursor specimen; hover only; Show cursor
```

The Help icon's bounds are the icon box only. The Tooltip is placed outside them, `space/xs` = 4 from the icon on the placement side, with its arrow pointing at the icon centre. So opening the tooltip never moves the Label or the field around it.

## Auto Layout relationship

- Tooltip: the root stacks `Content` and `Arrow row`; the `Arrow row` stretches to the Content's width (or height for `left`/`right`) so start, centre and end alignment are measured from the Content's edges.
- `Text and supporting text`: vertical stack inside the Content padding.
- Help icon: no Auto Layout; it is a positioned composition so the tooltip can sit outside its bounds.

## Flexible vs fixed children

| Layer | Horizontal | Vertical |
| --- | --- | --- |
| `Tooltip` (root) | Hug | Hug |
| `Content` | Hug, up to `size/width/xxs` | Hug |
| `Text` | Hug, wraps at the max width | Hug |
| `Supporting text` | Fill the Content | Hug |
| `Arrow row` | Fill (Fixed arrow height for top/bottom) | Fixed arrow height (Fill for left/right) |
| `Arrow` | Fixed | Fixed |
| `Help icon` | Fixed 16 | Fixed 16 |

# 6. Sizes and measurements

Tooltip has one size. Defaults:

| Measure | Text only | With supporting text |
| --- | --- | --- |
| Content padding | `space/md` = 8 top/bottom, `space/lg` = 12 left/right | `space/lg` = 12 on all sides |
| Text style | `type/body/xs/semibold` (12 / 18) | same |
| Supporting text style | — | `type/body/xs/medium` (12 / 18) |
| Text gap | — | `space/xs` = 4 |
| Max width | `size/width/xxs` = 320 | same; supporting text wraps at this width |
| Arrow | 16 × 6, inset `space/lg` = 12 from the Content edge for `-start` / `-end` | same |
| Radius | `radius/surface` | same |
| Text alignment | centre | start (left), for readable multi-line text |

Help icon: icon `size/icon/sm` = 16; tooltip distance from the icon `space/xs` = 4.

# 10. Guidelines content

Topics for `2.13 Tooltip · Guidelines`, in order. Each visual uses real Tooltip, Help icon, Icon button and field instances.

## When a Tooltip is right

Use a Tooltip to name an icon-only control, to identify an image, or to show the full text of a truncated label. Its content is a bonus: the interface must work without it.

Visual — a toolbar of Icon buttons with one Tooltip open ("Insert link"), next to a table cell with a truncated name and its Tooltip.

## Keep essential information visible

Instructions users need to complete a task — formats, rules, consequences — belong in the interface or in Help text (2.12). A Tooltip is hidden until hovered or focused and doesn't exist on touch screens.

Visual — Do/don't pair (`Doc/Do-dont`):
- Don't: a password field whose only requirements are inside a Help icon tooltip.
- Do: the same field with Help text "Use 8 or more characters with at least one number." and a Help icon tooltip that explains why ("Strong passwords protect shared workspaces.").

## Short title, optional supporting text

The Text is a short phrase. Supporting text is one or two short sentences that add detail; turn it on only when the Text alone is not enough. A tooltip is read in passing, never as a paragraph.

Visual — Do/don't pair:
- Don't: a Tooltip with a five-line paragraph and a list.
- Do: "Archive project" with supporting text "Archived projects are read-only. You can restore them at any time."

## Placement and collisions

Pick the side of the trigger with room to show the Tooltip; `top` is the default. The library keeps every placement as a variant; in the product, the Tooltip flips to the opposite side when it would leave the viewport, and the arrow follows. Use `-start` / `-end` when the trigger is near the left or right edge of the screen. Use `none` only when the Tooltip follows the pointer, for example over a chart.

Visual — the seven placements around one Icon button, then a trigger at the right edge of a frame showing `top` clipped and `top-end` fitting.

## Hover, focus, keyboard and touch

- A Tooltip opens on hover after a short delay and on keyboard focus immediately; it closes when the pointer leaves or focus moves, and on Escape.
- It stays open while the pointer moves from the trigger onto the Tooltip, so users can read it.
- On touch, Help icon opens its Tooltip on tap and closes on a second tap or a tap elsewhere; other Tooltips don't appear on touch, which is why they can't hold essential information.
- Disabled elements that can't be focused never get a Tooltip; explain unavailability in visible text instead.

Visual — Help icon in `rest`, `hover` (with cursor) and `focus` (with focus ring) side by side, captioned "hover", "keyboard focus", "tap".

## One family, many triggers

Help icon instances the Tooltip set; it doesn't draw its own surface. Edit the Tooltip once — colour, radius, padding, type — and every help icon in every field updates.

Visual — propagation example: (1) the Tooltip component with its Content radius highlighted, (2) the dependency arrow to `Help icon`, (3) a Label and a field showing the updated help tooltip.

## Content

- `Text` is a short phrase without a full stop ("Copy link", "Archive project"). For an icon-only control, it is the control's name.
- `Supporting text` uses full sentences with full stops.
- Don't repeat the trigger's visible label.
- No links, buttons or other interactive content in a Tooltip; use a popover or a dialog.
- Use sentence case.

## Accessibility

- The Tooltip is linked to its trigger as a description; for an icon-only trigger, the Tooltip text is also the accessible name.
- Help icon is a focusable button with an accessible name ("More information about Tax ID"); its Tooltip is its description.
- Tooltips appear on keyboard focus, not only on hover, and close on Escape without moving focus.
- Text on the inverse surface meets the text contrast threshold in every colour mode.
- Hover-only triggers with essential content are an accessibility failure, not a style choice.

# 11. QA

Fail QA when:
- the arrow is baked into separate, unrelated Tooltip drawings instead of the `.Main/Tooltip arrow` sibling of one Content;
- the arrow's fill is not the same variable as the Content fill;
- Help icon recreates the tooltip surface instead of instancing `Tooltip`;
- opening the Help icon tooltip changes the Help icon's bounds or moves the Label;
- supporting text uses a second typography or layout system instead of the shared `Text and supporting text` stack;
- the Help icon set cannot show every placement in `hover` and `focus`;
- the `focus` state is missing or looks the same as `hover`;
- the Tooltip grows wider than `size/width/xxs`;
- colours are raw values instead of `color/surface/inverse` and `color/text/inverse`.
