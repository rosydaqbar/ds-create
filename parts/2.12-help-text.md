# 2.12 Help text

Help text is the short line under a control. Before the user acts, it is a hint: the expected format, a limit, or what the value is used for. After validation fails, the same line becomes the error message, and its `Status` turns it to the danger colour.

Help text is the bottom row of every field. In `3.2 Text field` and `3.3 Choice field` it is stacked under a Label (2.11) and the control: **label → control → hint**. It is its own Part so hints and errors look and behave the same in every field.

# 1. Purpose

- Give users the information they need to fill a field correctly, always visible.
- Show a validation message in the same place, without changing the field's layout.

# 4. Property inventory

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm`, `md` | `md` |
| `Status` | variant | `none`, `invalid` | `none` |
| `Hint` | text | — | "This is a hint text to help the user." |

Variants: `Size` 2 × `Status` 2 = 4, e.g. `Size=md, Status=invalid`.

`Status=invalid` is the validation state. It is not a separate "destructive" set and not an interaction `State`: it describes the value, not the pointer or focus. The Text control (2.10) uses the same `Status` property, so a field sets both to the same value.

## Auto Layout relationship

```text
Field (3.2 / 3.3, not part of this Part)
layout: Vertical
gap: space/sm
├─ Label (2.11)
├─ Control
└─ Help text                 ← this Part
```

The field owns the gap. Help text adds no margin of its own, so the hint and the error sit exactly in the same place.

## Flexible vs fixed children

| Layer | Horizontal | Vertical |
| --- | --- | --- |
| `Help text` (root) | Hug in the set; Fill in a field | Hug |
| `Text` | Hug in the set; Fill in a field (wraps) | Hug |

A message never widens the field. When it is longer than the field width, it wraps to a second line under the control.

# 6. Sizes and measurements

| Size | Text style | Pairs with |
| --- | --- | --- |
| `sm` | `type/body/xs/regular` (12 / 18 by default) | `Size=sm` controls and `Label Size=sm` |
| `md` | `type/body/sm/regular` (14 / 20 by default) | `Size=md` and `Size=lg` controls and `Label Size=md` |

Gap between the control and the Help text: `space/sm` = 6 by default (owned by the field).

# 7. States

| Status | Text colour | Meaning |
| --- | --- | --- |
| `none` | `color/text/tertiary` | hint, shown before or while the user acts |
| `invalid` | `color/text/danger` | validation message after the value fails a check |

Layout, size and position are identical in both. Only the colour and the copy change.

# 10. Guidelines content

Topics for `2.12 Help text · Guidelines`, in order. Each visual uses real Label, Text control and Help text instances.

## Hint first, then error

Show a hint when users need it before they type: a format, a limit, a consequence. When validation fails, replace the hint with the error message in the same place. Don't stack a hint and an error.

Visual — a sequence of three states of one field: (1) empty with the hint, (2) filled with an invalid value and the error replacing the hint, (3) fixed value with the hint back. Arrows between the steps.

## Validation is not only colour

The error message is text that says what went wrong; the control also turns `Status=invalid`. Colour supports the message; it never carries it alone.

Visual — Do/don't pair:
- Don't: control with `Status=invalid` and no message, or a message that only says "Invalid".
- Do: control with `Status=invalid` and "Enter a date after 1 January 2026."

## Essential information stays visible

Formats, limits and requirements go in Help text, not in a Tooltip or the placeholder. Tooltips are hidden until hovered and don't exist on touch; placeholders disappear on typing.

Visual — Do/don't pair:
- Don't: placeholder "DD/MM/YYYY" with no hint.
- Do: Help text "Use the format DD/MM/YYYY." under an empty control.

## Long messages wrap

A message that is longer than the field wraps under the control; the field never grows wider. Keep messages to two lines at the field width.

Visual — a field at its standard width with a two-line message, `Doc/Measure` on the field width.

## Content

- Hints describe the expected value; they don't repeat the Label ("Use 8 or more characters", not "Enter your password").
- Error messages say what went wrong and how to fix it, in plain words: "Enter an email address like name@example.com."
- Don't blame the user ("You entered an invalid email") and don't use codes ("Error 422").
- Use sentence case. End full sentences with a full stop.
- One sentence, two lines at most at the field width.

## Accessibility

- The field links Help text to its control as the control's description, so it is read after the Label.
- A validation message that appears after the user acts is announced politely, without moving focus.
- Hint and error text meet the text contrast threshold on the surface behind them in every colour mode.

# 11. QA

Fail QA when:
- hint and error are separate components, or the error is a separate set instead of `Status=invalid`;
- the error message moves, changes size or adds space compared with the hint;
- the Help text has its own top margin instead of relying on the field gap;
- long messages widen the field instead of wrapping;
- a field draws its own hint text instead of instancing `Help text`;
- colours are raw values instead of `color/text/tertiary` and `color/text/danger`.
