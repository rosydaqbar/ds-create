# 2.4 Badge

Badges communicate compact secondary information: status, counts, categories and metadata. They are labels, not actions. The page holds the `Badge` set. A badge paired with a short announcement message is the Badge group Component (3.8).

Related pages: removable, countable or selectable chips → 2.5 Tag; buttons → 2.1 Button; badge + announcement message → 3.8 Badge group.

# 2. Badge

Published set: `Badge`

Variant name pattern: `Size=md, Type=pill, Tone=neutral, Icon only=false`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `md` | height, padding, label style |
| `Type` | variant | `pill, rounded, outline` | `pill` | pill: full radius with tinted fill; rounded: small radius with tinted fill; outline: neutral surface and border, color carried by the dot or icon |
| `Tone` | variant | `neutral, brand, danger, warning, success, info` and the category families `slate, sky, blue, indigo, purple, pink, orange` | `neutral` | colors |
| `Icon only` | variant | `false, true` | `false` | a square/circular badge with one icon and no label |
| `Label` | text | — | "Label" | visible text |
| `Show dot` | boolean | — | `false` | leading status dot |
| `Show flag` | boolean | — | `false` | leading country flag |
| `Show avatar` | boolean | — | `false` | leading avatar (2.6 Avatar, `Size=2xs`) |
| `Show leading icon` | boolean | — | `false` | leading icon |
| `Show trailing icon` | boolean | — | `false` | trailing icon |
| `Show close` | boolean | — | `false` | trailing `.Main/Badge close` |
| `Flag` | instance swap | flags (1.8 Brand assets) | — | — |
| `Leading icon` | instance swap | icons | `arrow-up` | also the icon of `Icon only=true` |
| `Trailing icon` | instance swap | icons | `arrow-right` | — |

Variant count: 3 sizes × 3 types × 13 tones × 2 icon-only = **234 variants**. The leading visuals and trailing actions are booleans so one variant covers every content mode.

Rules:
- Use one leading visual at a time (dot, flag, avatar or icon), and one trailing element at a time (trailing icon or close).
- Optional visuals change the internal gap, never the root component.
- Do not rebuild each type, tone or icon mode as an unrelated component or set.

## 2.1 Badge anatomy

```text
Badge
layout: Horizontal
align: Center
padding: badge/padding-x/{Size} left and right, badge/padding-y/{Size} top and bottom
gap: badge/gap/{Size}
width: Hug, height: Hug

├─ Dot                                  optional (Show dot), size/indicator/xs
├─ Flag                                 optional (Show flag), instance swap
├─ Avatar                               optional (Show avatar), 2.6 Avatar instance
├─ Leading icon                         optional (Show leading icon)
├─ Label                                text, single line; hidden when Icon only=true
├─ Trailing icon                        optional (Show trailing icon)
└─ Close                                optional (Show close), .Main/Badge close instance
```

When a leading visual or the close is on, the padding on that side tightens (`badge/padding-x-tight/{Size}`) so the visual sits optically centered against the rounded end.

`Icon only=true`: the root is square (`rounded`, `outline`) or circular (`pill`), equal padding, one `Leading icon`.

Auto Layout relationship:

| Node | Direction | Width | Height |
| --- | --- | --- | --- |
| `Badge` | Horizontal, centered | Hug | Hug |
| `Label` | — | Hug, single line | Hug |
| visuals, close | — | Fixed | Fixed |

The label never wraps. Long labels are shortened by content rules, not by shrinking the type.

# 5. States

Badge is read-only and has no states. Only its close part is interactive:

| `.Main/Badge close` State | What changes |
| --- | --- |
| `rest` | icon in the tone's icon color |
| `hover` | a small tinted background behind the icon (`color/fill/{tone}/subtle/hover`) |

# 7. Token map

Semantic tones (`{tone}` = `neutral`, `brand`, `danger`, `warning`, `success`, `info`):

| Part | Type=pill, rounded | Type=outline |
| --- | --- | --- |
| Root fill | `color/fill/{tone}/subtle` | `color/surface/base` |
| Root border | `color/border/{tone}/subtle` (neutral: `color/border/subtle`) | `color/border/default` |
| Label | `color/text/{tone}` (neutral: `color/text/secondary`) | `color/text/secondary` |
| Dot, icons | `color/icon/{tone}` (neutral: `color/icon/tertiary`) | `color/icon/{tone}` |

| Part | Type=pill, rounded | Type=outline |
| --- | --- | --- |
| Root fill | `color/category/{family}/subtle` | `color/surface/base` |
| Root border | `color/category/{family}/border` | `color/border/default` |

| Dot, icons | `color/category/{family}/solid` | `color/category/{family}/solid` |

# 8. Guidelines

## 8.1 Badge, Tag, text label or Button
Visual: four rows — a status Badge in a table, a removable Tag in a filter bar, plain metadata text, a Button. Rule: Badge labels; Tag holds a value the user manages; text is enough when no emphasis is needed; Button acts.

## 8.2 Anatomy
Show the Badge anatomy (optional dot / flag / avatar / icon → label → optional trailing icon or close), each optional part labeled with the boolean that shows it.

## 8.3 Type, tone, size and icon modes
- Type: pill for status and counts, rounded for categories and metadata, outline when many badges sit together and color would be noisy.
- Size: match the text around it (`sm` in dense tables and navigation, `md` by default, `lg` in headers).
- Visual: one row per property showing each value.

## 8.4 Choosing a tone
- Semantic tones carry meaning: `success` done, `warning` needs attention, `danger` failed or blocked, `info` neutral information, `brand` new or featured, `neutral` inactive or default.
- Category tones (`slate` … `orange`) carry no meaning; use them only to separate groups (projects, teams, topics).
- Color or a dot alone never carries status. The label always names it.
- Visual: the same status column in color and in grayscale — still readable because of the words.

## 8.5 Content and long labels
- Badges stay compact; labels are one or two words.
- Labels never wrap and are never truncated mid-word; shorten the label instead.
- Counts above 99 show "99+".
- Visual: a long label badge (don't) next to the shortened label (do).

## 8.6 Removable badges
- `Show close` implies the badge represents removable content (an applied filter), not a generic action.
- The close target reaches `size/touch-min` in code on touch platforms; the close has an accessible name ("Remove filter Design").
- When users manage many values, use 2.5 Tag instead.

## 8.7 Accessibility
- Label text meets text contrast against the badge fill in every tone and mode.
- Status is never color-only.
- A badge is not focusable; only its close part is.

## 8.8 Do / don't
- Do: "Pending review" with a warning dot. Don't: a colored dot with no label.
- Don't: a badge with a full sentence.
- Don't: a badge used as a button ("Upgrade" badge that opens checkout).
- Don't: category colors for status, or status colors for decoration.

## 8.9 Maintenance
To change every badge at once, edit the tone tokens (`color/fill/{tone}/subtle`, `color/text/{tone}`, `color/category/*`) or `.Main/Badge close`. Never edit individual variants.

# 9. QA

Fail QA when:
- icon or content modes became separate component sets;
- a `Badge group` set is published on this page (it belongs to 3.8);
- category tones are missing;
- close behavior is not handled by `.Main/Badge close`;
- the matrix does not expose the full Type × Tone × Size relationship;
- status is shown by color alone in any Overview or Guidelines example;
- property names from the old model remain (`Color`, `Icon=Dot`, `Badge color`, `Badge modern`).
