# 2.8 Radio

The Radio Part is the round control that marks one choice in a set of mutually exclusive options. Choosing one option clears the others.

The labeled radio, radio groups and the richer option cards (with icons, avatars, payment logos and supporting text, for mobile and desktop) live on 3.3 Choice field, which instances this Part. Radio shares its sizes, border, fill and focus tokens with 2.7 Checkbox so both read as one family.

# 2. Published set and properties

Published set: `Radio`

Variant name pattern: `Size=md, Checked=false, State=rest`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `sm, md` | `sm` | ring and dot size |
| `Checked` | variant | `false, true` | `false` | empty ring, or ring with dot |
| `State` | variant | `rest, hover, focus, disabled` | `rest` | interaction treatment |

Variant count: 2 × 2 × 4 = **16 variants**.

A radio has no mixed state. Mixed is not a meaningful end-state for a single choice and is never exposed.

# 4. Sizes and measurements

| Size | Ring | Dot |
| --- | --- | --- |
| `sm` | `radio/size/sm` = 16 (same as `checkbox/size/sm`) | `size/indicator/xs` = 6 |
| `md` | `radio/size/md` = 20 (same as `checkbox/size/md`) | `size/indicator/sm` = 8 |

- `sm` pairs with `type/body/sm` labels, `md` with `type/body/md` labels.
- On its own, the radio reaches `size/touch-min` through hit-area padding in code; in rows and cards, the row or card is the hit target.

# 5. States and matrix layout

| State | What changes |
| --- | --- |
| `rest` | unchecked: surface + border; checked: brand fill + on-solid dot |
| `hover` | unchecked: brand border and tint; checked: fill moves to its hover child |
| `focus` | rest + `focus/default` ring (round) |
| `disabled` | disabled fill, border and dot |

Matrix:

```text
                       rest   hover   focus   disabled      ← columns: State
sm   Checked=false
     Checked=true                                             ← rows: Size × Checked
md   Checked=false
     Checked=true
```

# 7. Guidelines

## 7.1 Single-choice semantics
- One option in a group is always checked; start with a sensible default checked.
- Choosing an option clears the previous one.
- When several options may be chosen together, use 2.7 Checkbox. The checkbox-style option cards on 3.3 are the intentional multi-select version of the same card layout.

## 7.2 Checked vs focus
- Checked is the dot; focus is the ring around the control. They look different and can appear together.
- Visual: four radios — unchecked, checked, focused unchecked, focused checked — captioned "Focus is never selection."

## 7.3 Radio, Select, Checkbox or Switch
Visual: the same "Billing period" choice as radios (3 options, all visible), as a 3.5 Select (12 options), and why it is not a Checkbox or a Switch.

## 7.4 Accessibility
- Arrow keys move the selection within a group; Tab enters and leaves the group.
- The group has a label (3.3 Choice field) announced with each option.
- Selection is shown by the dot, not by color alone; the unchecked ring meets non-text contrast (3:1).

## 7.5 Do / don't
- Don't: two radios checked in the same group.
- Don't: a lone radio (use Checkbox for one statement).
- Don't: focus styled like the checked state.
- Don't: radio groups with no option checked by default when one option is the safe choice.

## 7.6 Maintenance
Change the shared tokens in §6 to update Radio and Checkbox together. Change this set to update every radio inside 3.3 Choice field.

# 8. QA

Fail QA when:
- a mixed state exists;
- Radio uses different fill, border or focus tokens from Checkbox;
- checked and focus look identical;
- the dot is off-center at any size;
- radio groups, option cards or labels are built on this page instead of 3.3;
- property names from the old model remain (`Selected`, `Type=Radio`, `Default`, `Focused`).
