# 2.5 Tag

Tags (chips) are compact elements that hold a value the user manages: an applied filter they can remove, a topic with a count, an option they can select, or a value inside a multi-value input. Unlike a Badge, a Tag is interactive.

Related pages: read-only status and metadata → 2.4 Badge; the checkbox inside selectable tags → 2.7 Checkbox (instanced); multi-value fields → 3.2 Text field and 3.5 Select.

# 2. Published set and properties

Published set: `Tag`

Variant name pattern: `Size=md, Type=removable, State=rest`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `sm, md, lg` | `md` | height, padding, label style, part sizes |
| `Type` | variant | `text, removable, count` | `text` | trailing element: none, `.Main/Tag close`, or `.Main/Tag count` |
| `State` | variant | `rest, hover, focus, disabled` | `rest` | container and part states |
| `Label` | text | — | "Label" | visible text |
| `Count` | text | — | "5" | count value, `Type=count` only |
| `Show checkbox` | boolean | — | `false` | leading 2.7 Checkbox; the nested Checkbox's `Checked` is exposed on the Tag |
| `Show dot` | boolean | — | `false` | leading dot |
| `Show flag` | boolean | — | `false` | leading country flag |
| `Show avatar` | boolean | — | `false` | leading 2.6 Avatar |
| `Flag` | instance swap | flags (1.8 Brand assets) | — | — |

Variant count: 3 sizes × 3 types × 4 states = **36 variants**. With the leading booleans and the exposed `Checked`, every combination of visual, action and selection is reachable without extra variants.

Rules:
- `Type` holds the trailing element, so a tag never combines close and count.
- Use one leading visual at a time (dot, flag or avatar). The checkbox may sit before it.

# 3. Anatomy

```text
Tag
layout: Horizontal
align: Center
height: tag/height/{Size} (Fixed)
padding: tag/padding-x/{Size} left and right
gap: tag/gap/{Size}
width: Hug

├─ Checkbox                             optional (Show checkbox), 2.7 Checkbox instance, Size=sm
├─ Dot                                  optional (Show dot)
├─ Flag                                 optional (Show flag)
├─ Avatar                               optional (Show avatar), 2.6 Avatar, Size=2xs
├─ Label                                text, single line, Hug
├─ Close                                Type=removable: .Main/Tag close instance
└─ Count                                Type=count: .Main/Tag count instance
```

When a trailing element is present, the trailing padding tightens (`tag/padding-x-tight/{Size}`) so the close or count sits optically centred against the edge.

# 5. States

| State | What changes |
| --- | --- |
| `rest` | base tokens |
| `hover` | container fill moves to its hover child; close part shows its hover background |
| `focus` | `focus/default` ring around the tag (or around the close when only the close is focusable) |
| `disabled` | label, visuals and border use disabled tokens; close and checkbox disabled |

Selected (checked) tags keep the same container; the Checkbox shows the selection so it never relies on colour alone.

# 8. Guidelines

## 8.1 Tag, Badge, filter control or Button
Visual: a filter bar showing removable Tags (applied filters), a Badge in a table (read-only), a Button "Add filter" (action). Rule: Tag = a value the user manages.

## 8.2 Anatomy
Show the four composition trees (text, removable, count, selectable) as real instances side by side with callouts on checkbox, leading visual, label and trailing element.

## 8.3 Removable vs selectable
- Removable: the close removes the value from a list or filter. The whole tag is not a button; only the close is.
- Selectable: the checkbox toggles the value; the whole tag is the hit target.
- Visual: the same "Design" tag in both behaviours with the hit areas outlined.

## 8.4 Size and interaction of parts
- Close and checkbox scale with the tag (§4).
- Show the close and checkbox states side by side: rest, hover, focus, disabled.

## 8.5 Label length and wrapping
- Tags stay compact; labels are one to three words.
- Long labels never force smaller padding or type. In a row, tags wrap to the next line; inside a field, the field grows.
- Visual: a long label squeezed with tiny padding (don't) next to a shortened label in a wrapping row (do).

## 8.6 Supporting visuals
Country flags and avatars support the label; they are never the only meaning. Always show the name next to the flag or avatar.

## 8.7 Accessibility
- Removable tags: the close has an accessible name ("Remove Design"), is reachable by keyboard, and reaches `size/touch-min` in code on touch platforms.
- Selectable tags: the checkbox state is announced; focus stays visible.
- Disabled tags are announced as disabled, not only greyed out: the selectable tag and the close carry `aria-disabled` (parts/00-parts.md §13).
- Label contrast meets text contrast in every mode.

## 8.8 Do / don't
- Do: one trailing action. Don't: close and count on the same tag.
- Do: shorten long labels. Don't: tiny type to fit a long label.
- Don't: a flag or avatar alone without a name.
- Don't: tags as navigation links or primary actions.

## 8.9 Maintenance
Edit `.Main/Tag close`, `.Main/Tag count` or the 2.7 Checkbox to change every tag. Colour changes go through the tokens in §7.

# 9. QA

Fail QA when:
- close, count or checkbox are drawn separately in each variant instead of instancing `.Main/Tag close`, `.Main/Tag count` or 2.7 `Checkbox`;
- removable or selectable tags have no explicit interaction part;
- leading visuals shift label alignment inconsistently;
- close and count can appear together;
- the full property matrix is reduced to a handful of chip examples;
- focus is missing on removable or selectable tags;
- a disabled tag or close is shown as disabled but not announced as disabled.
