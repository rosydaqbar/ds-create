# 2.2 Icon button

An Icon button is a compact square action with one icon and no visible label. It covers quiet tool actions (copy, edit, more, settings in a toolbar or table row) and the close action of dialogs, drawers, banners and notifications.

It is not a smaller version of 2.1 Button. A Button with `Icon only=true` sits in a row of labelled buttons and carries their emphasis (including primary); an Icon button is a quieter utility control that sits inside content, toolbars and surface corners.

# 2. Published set and properties

Published set: `Icon button`

Variant name pattern: `Size=md, Emphasis=tertiary, State=rest`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `xs, sm, md, lg` | `md` | side length, padding, icon size |
| `Emphasis` | variant | `secondary, tertiary` | `tertiary` | bordered surface, or no container at rest |
| `State` | variant | `rest, hover, pressed, focus, disabled, loading` | `rest` | interaction treatment |
| `Icon` | instance swap | icons | `x` | the glyph; the close action is `Icon=x` |

Variant count: 4 sizes × 2 emphasis × 6 states = **48 variants**.

Rules:
- Close is not a separate set. It is `Icon button` with the `x` icon.
- Dark surfaces are handled by colour mode, not by a `Dark background` variant. Put the instance in a frame set to the Dark mode (or the surface's inverse mode) and its tokens resolve correctly.
- No primary emphasis and no danger tone: a primary or destructive icon-only action belongs to 2.1 Button with `Icon only=true`.

# 3. Anatomy

```text
Icon button
layout: Horizontal
align: Center / Center
width = height = icon-button/size/{Size} (Fixed, square)
padding: none; the icon is centred in the fixed square

├─ Icon                                 icon instance, Fixed size/icon/{icon step}; hidden when State=loading
└─ Spinner                              State=loading only: 2.15 Spinner, Size=sm (xs, sm) or md (md, lg), colour = icon colour
```

Auto Layout relationship:

| Node | Direction | Width | Height | Padding |
| --- | --- | --- | --- | --- |
| `Icon button` | Horizontal, centred | Fixed (square) | Fixed (square) | none (equal space comes from centring) |
| `Icon` | — | Fixed | Fixed | — |

The icon is always centred, so the space around it is equal on all sides. Nothing is optional; nothing grows.

# 4. Sizes and measurements

| Size | Side | Icon | Padding (result) |
| --- | --- | --- | --- |
| `xs` | `icon-button/size/xs` = 28 | `size/icon/sm` = 16 | 6 |
| `sm` | `icon-button/size/sm` = 32 | `size/icon/sm` = 16 | 8 |
| `md` | `icon-button/size/md` = 36 | `size/icon/md` = 20 | 8 |
| `lg` | `icon-button/size/lg` = 44 | `size/icon/lg` = 24 | 10 |

The side and the icon are bound; the padding is what remains, split equally around the centred icon.

- `xs` and `sm` are for dense toolbars and table rows (the former utility actions).
- `sm`, `md` and `lg` are for close actions (sm in tags and toasts, md in banners and drawers, lg in dialogs).
- On touch platforms every size reaches `size/touch-min` through hit-area padding in code; the visual size does not change.

# 5. States

| State | What changes |
| --- | --- |
| `rest` | secondary: surface + border; tertiary: no visible container |
| `hover` | container fill moves to its hover token; icon darkens |
| `pressed` | container fill moves to its pressed token |
| `focus` | rest tokens + `focus/default` ring |
| `disabled` | icon and border use disabled tokens |
| `loading` | rest container; Spinner replaces the icon; not clickable |

Focus stays visibly distinct from hover. The tertiary root keeps a bound `color/fill/none` fill and clip content on so the focus ring renders.

# 8. Guidelines

## 8.1 Icon button, icon-only Button, or labelled Button
Show the three side by side in context:
- labelled Button: the action needs words or is the main action;
- `Button, Icon only=true`: an icon action inside a row of labelled buttons, sharing their height and emphasis;
- Icon button: a quiet tool or close action inside content.

## 8.2 Close actions
- Always `Icon=x`; place it in the top-right corner of the surface, aligned to the first line of the title.
- Size follows the surface: `sm` for tags and toasts, `md` for banners and drawers, `lg` for dialogs.
- Visual: three surfaces (toast, banner, dialog) with their close button and `Doc/Measure` guides for the corner offset.

## 8.3 Dark surfaces through colour mode
Show the same instance on a light surface and inside a frame set to the Dark mode. Annotate: "Same component, same variant. The frame's colour mode switches the tokens." This replaces the old dark-background variant.

## 8.4 Content
- Use only icons whose meaning is widely understood (close, more, copy, edit, delete, settings). When in doubt, use a labelled Button.
- Every Icon button has an accessible name in code and shows a Tooltip (2.13) with that name on hover and focus.

## 8.5 Accessibility
- Visible focus ring on every emphasis.
- Icon contrast meets the non-text threshold (3:1) against its surface.
- Hit area reaches `size/touch-min` on touch platforms.

## 8.6 Do / don't
- Do: `x` close in the dialog corner. Don't: a text "Close" link in the same corner.
- Do: one row of tool icons with the same size and emphasis. Don't: mixed sizes in one toolbar.
- Don't: an Icon button for the primary action of a view.
- Don't: a separately drawn "dark" close button.

# 9. QA

Fail QA when:
- close exists as its own component set;
- a `Dark background` or similar variant exists instead of colour-mode behaviour;
- the icon is off-centre or padding is unequal;
- the square side is not bound to `icon-button/size/{Size}`;
- focus is missing or identical to hover;
- loading does not instance 2.15 Spinner;
- the tertiary focus ring does not render;
- the colour-mode row is missing from `· Component`.
