# 2.10 Text control

The Text control is the box people type into or open: a single-line input, a multi-line text area, or the trigger of a select. It holds the value or placeholder, optional leading and trailing adornments, and the interaction and validation treatment. It has no label and no hint.

Related pages:
- label, required marker and help icon above the box → 2.11 Label;
- hint and validation message under the box → 2.12 Help text;
- the complete field (label + control + hint) and the special input types (leading or trailing dropdown, payment, tags inside or outside, trailing button, password reveal, date and time, number counters, file upload, verification code) → 3.2 Text field;
- the select with its open menu, menu items, multi-select and scroll bar → 3.5 Select.

Important product note: on mobile, the value text is at least 16 (`font/size/input-min`) so browsers don't zoom into the field when it is focused.

# 2. Published set and properties

Published set: `Text control`

Variant name pattern: `Type=single-line, Size=md, Filled=false, Status=none, State=rest`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Type` | variant | `single-line, multi-line, select` | `single-line` | structure: one line, text area, or trigger with chevron |
| `Size` | variant | `sm, md, lg` | `md` | height, padding, text style |
| `Filled` | variant | `false, true` | `false` | placeholder or entered value |
| `Status` | variant | `none, invalid` | `none` | validation treatment and status icon |
| `State` | variant | `rest, hover, focus, disabled` | `rest` | interaction treatment |
| `Text` | text | — | "Placeholder" | the placeholder or the value |
| `Supporting text` | text | — | "@olivia" | secondary text after the value (select) |
| `Prefix` | text | — | "https://" | static prefix segment |
| `Show leading icon` | boolean | — | `false` | — |
| `Leading icon` | instance swap | icons | `mail` | — |
| `Show avatar` | boolean | — | `false` | leading 2.6 Avatar, `Size=xs` |
| `Show dot` | boolean | — | `false` | leading status dot |
| `Show prefix` | boolean | — | `false` | prefix segment (single-line) |
| `Show supporting text` | boolean | — | `false` | — |
| `Show help icon` | boolean | — | `false` | trailing 2.13 `Help icon` |
| `Show shortcut` | boolean | — | `false` | trailing 2.17 Kbd |
| `Show trailing icon` | boolean | — | `false` | a trailing icon (for example the password reveal eye) |
| `Trailing icon` | instance swap | icons | `eye` | — |
| `Show resize handle` | boolean | — | `true` | multi-line only |

Variant count: 3 types × 3 sizes × 2 filled × 2 status × 4 states = **144 variants**.

Rules:
- `Status=invalid` is validation; `State` is interaction. They combine: an invalid field can be focused or hovered. Never use a separate set for errors.
- `Filled` switches the text colour between placeholder and value; the text layer is the same.
- Use one leading visual at a time (icon, avatar or dot).

Single-line and select:

Multi-line:

```text
Text control
layout: Vertical
align: Top / Left

padding: text-control/padding-y-multiline top and bottom, text-control/padding-x/{Size} left and right

border, radius, clip: as single-line

├─ Text                                 Fill width, top-aligned, wraps

```

## Auto Layout relationship

| Node | Direction | Width | Height |
| --- | --- | --- | --- |
| `Text control` | Horizontal (multi-line: Vertical) | Fill | Fixed `size/control/{Size}` (multi-line: Hug, min `text-control/multiline-min-height`) |
| `Prefix` | Horizontal | Hug | Fill |
| `Content` | Horizontal | Fill | Hug |
| `Text` | — | Fill | Hug |
| Adornments | — | Fixed | Fixed |

Flexible vs fixed:
- `Content` and `Text` fill; every adornment stays fixed or hugs.
- Leading visuals never shift the text baseline between types.
- Multi-line text is top-aligned and never vertically centred.

The Type property is not cosmetic: `select` adds the chevron and is opened as a whole; `multi-line` changes the direction and height behaviour; `single-line` allows the prefix.

# 4. Sizes and measurements

| Size | Height | Padding-x | Gap | Text style | Leading icon | Help / status icon |
| --- | --- | --- | --- | --- | --- | --- |
| `sm` | `size/control/sm` = 36 | `text-control/padding-x/sm` = 12 | `space/md` = 8 | `type/body/sm/regular` | `size/icon/md` = 20 | `size/icon/sm` = 16 |
| `md` | `size/control/md` = 40 | `text-control/padding-x/md` = 12 | `space/md` = 8 | `type/body/md/regular` | `size/icon/md` = 20 | `size/icon/sm` = 16 |
| `lg` | `size/control/lg` = 44 | `text-control/padding-x/lg` = 14 | `space/md` = 8 | `type/body/md/regular` | `size/icon/md` = 20 | `size/icon/sm` = 16 |

- Heights match Button `sm`, `md`, `lg`, so a control and a button sit in one row without adjustment.
- Multi-line: minimum height `text-control/multiline-min-height` = 128 at `md` by default; padding 12 top and bottom (`text-control/padding-y-multiline`), 14 left and right; the resize handle sits in the bottom-right corner (12 × 12, inset 6).
- Prefix: padding-x as the control, a right border `color/border/default`; the Content gap follows it.
- On mobile the value text never goes below `font/size/input-min` (16), whatever the size.
- The width is set by the parent (form column, filter row). The default demo width is 320.

# 5. States and status

| State | What changes |
| --- | --- |
| `rest` | default border, base fill |
| `hover` | border strengthens |
| `focus` | brand border + `focus/default` ring; remains distinct from hover |
| `disabled` | disabled fill and text; the value stays legible enough to identify the field; adornments disabled |

| Status | What changes |
| --- | --- |
| `none` | as above |
| `invalid` | danger border in every state, `focus/danger` ring on focus, `Status icon` shown at the trailing edge; the message itself comes from 2.12 Help text |

Placeholder (`Filled=false`) shows the placeholder colour; filled (`Filled=true`) shows the value colour. The select trigger in its open state is `State=focus`; the menu belongs to 3.5.

# 8. Guidelines

## 8.1 Which type
- `single-line` for short values: names, emails, numbers, search.
- `multi-line` for free text longer than one line: comments, descriptions, messages.
- `select` for choosing one value from a list the system knows; it opens 3.5 Select's menu.
- Visual: the three types with the same label, captioned with their use.

## 8.2 Anatomy: label → control → hint
Show 2.11 Label above, this control, and 2.12 Help text below, as they come together on 3.2 Text field, with this Part highlighted. Caption: "The box is the Part; the field is the Component."

## 8.3 Status vs state
- State is interaction (hover, focus, disabled). Status is validation (invalid).
- Visual: invalid at rest, invalid on hover, invalid on focus — all three keep the danger border; only focus adds the ring.
- The error message always appears as 2.12 Help text; the status icon and border alone are not enough.

## 8.4 Adornments
- Leading icon: names the kind of value (mail, search, calendar).
- Prefix: static text that is part of the value but not typed (`https://`, a currency symbol).
- Avatar, dot: for select values that are people or statuses.
- Help icon: opens a 2.13 Tooltip with more context.
- Shortcut: shows the keyboard shortcut that focuses the control.
- Trailing icon: a small action on the value (show/hide password).
- Visual: each adornment on its own control, then a "don't" with three adornments crowding one control.

## 8.5 Multi-line behaviour
- Text starts at the top-left and wraps; the control grows with content up to the layout's limit, then scrolls.
- The resize handle lets people enlarge it on desktop.
- Visual: a centred multi-line text (don't) next to the top-aligned one (do).

## 8.6 Placeholder and value content
- Placeholders show an example of the expected format ("you@company.com"), never the label, and never instructions people need after they start typing.
- Long values truncate with an ellipsis in single-line and select; they wrap in multi-line.

## 8.7 Mobile text size
On mobile, value text is at least 16 so the browser does not zoom into the field on focus. Visual: the same field at `sm` on desktop (14) and on mobile (16).

## 8.8 Accessibility
- Every control has a visible label in product (3.2 Text field). Placeholder is never the label.
- Focus is always visible and distinct from hover; invalid fields keep the ring on focus.
- Border meets non-text contrast (3:1) against the surface; text meets text contrast.
- Disabled values stay legible; prefer read-only over disabled when people need to copy the value.
- A disabled control is announced as disabled. Native inputs do this themselves; a custom `select` trigger or any non-native box carries `aria-disabled` (parts/00-parts.md §13).

## 8.9 Do / don't
- Do: placeholder as an example. Don't: placeholder as the label.
- Do: invalid border + Help text message. Don't: a red border with no message.
- Don't: vertically centred multi-line text.
- Don't: a select trigger built from a single-line control with a chevron icon pasted in.

# 9. QA

Fail QA when:
- the label, required marker or hint is part of this Part (they belong to 2.11, 2.12 and 3.2);
- `Content` does not fill while adornments stay fixed or hug;
- multi-line text is vertically centred;
- invalid is a separate set or uses `Destructive`;
- placeholder and filled are different text layers or different components;
- the select trigger's chevron is not part of `Type=select`;
- the shortcut is not a 2.17 Kbd instance, the help icon is not a 2.13 Help icon instance, or the avatar is not a 2.6 Avatar instance;
- the 144-variant matrix is replaced with a small showcase;
- the mobile minimum text size is not documented;
- property names from the old model remain (`Destructive`, `Placeholder`/`Filled` as states, `Focused`);
- a disabled `select` trigger or other non-native box is shown as disabled but not announced as disabled.
