# 2.11 Label

A Label names a form control. It sits above a Text control (2.10), a group of Checkboxes (2.7) or Radios (2.8), a Select or a Slider, and can mark the field as required and offer a help icon with a short explanation.

Label is the top row of every field. In `3.2 Text field` and `3.3 Choice field` it is stacked with the control and a Help text (2.12): **label → control → hint**. The Label is its own Part so every field in the system names itself the same way, and so a change to label type, colour or the required marker propagates everywhere at once.

# 1. Purpose

- Give every control a visible, persistent name that stays readable while the user types.
- Mark a field as required with one consistent marker.
- Offer optional, non-essential explanation through a help icon that opens a Tooltip.

# 4. Property inventory

Property order (variant names follow this order):

| Property | Type | Values | Default |
| --- | --- | --- | --- |
| `Size` | variant | `sm`, `md` | `md` |
| `Label` | text | — | "Label" |
| `Show required` | boolean | — | false |
| `Show help icon` | boolean | — | false |

Variants: `Size` 2 = 2 variants, e.g. `Size=md`.

Label has no `State`: it takes no input, so hover, focus, pressed and disabled belong to the control it names. A disabled field keeps the Label at its normal colour (§10).

# 5. Anatomy

```text
Label
layout: Horizontal
align: Center
gap: space/xxs
width: Hug (Fill when placed in a field)
height: Hug

├─ Text                               Hug; single line
├─ Asterisk                           Hug; optional (Show required)
└─ Help icon                          instance of Help icon, State=rest; optional (Show help icon)
```

Layer rules:
- `Text` holds the Label text property.
- `Asterisk` is a text layer holding the glyph `*`. It is a marker, not copy, so it has no text property and is never typed into the Label text.
- `Help icon` is an instance of the published `Help icon` (2.13), not a loose icon. Its tooltip is positioned outside its bounds, so opening it never shifts the Label or the field below.

## Auto Layout relationship

```text
Field (3.2 / 3.3, not part of this Part)
layout: Vertical
gap: space/sm
├─ Label                     ← this Part
├─ Control
└─ Help text (2.12)
```

Inside the Label, the three children sit on one horizontal row, centred vertically, with `space/xxs` between them. The help icon follows the marker directly; it is not pushed to the far edge of the field.

## Flexible vs fixed children

| Layer | Horizontal | Vertical |
| --- | --- | --- |
| `Label` (root) | Hug in the set; Fill when a field stretches it | Hug |
| `Text` | Hug | Hug |
| `Asterisk` | Hug | Hug |
| `Help icon` | Fixed (icon box) | Fixed (icon box) |

`Text` never truncates inside the Part. If a label is too long for the field width, the label copy is too long (§10 Content).

# 6. Sizes and measurements

| Size | Text style | Asterisk style | Help icon box | Gap | Pairs with |
| --- | --- | --- | --- | --- | --- |
| `sm` | `type/body/xs/medium` (12 / 18 by default) | same as Text | `size/icon/xs` = 12 | `space/xxs` = 2 | `Size=sm` controls in dense layouts |
| `md` | `type/body/sm/medium` (14 / 20 by default) | same as Text | `size/icon/sm` = 16 | `space/xxs` = 2 | `Size=md` and `Size=lg` controls |

In a field, the Label sits `space/sm` = 6 above the control by default (owned by the field Component, not by the Label).

# 7. States

None on the Label. When the control is disabled, the Label stays at its rest colours.

# 10. Guidelines content

Topics for `2.11 Label · Guidelines`, in order. Each visual uses real Label, Text control and Help text instances.

## Every control has a visible Label

A placeholder disappears as soon as the user types, and a Tooltip is hidden until hovered. Neither replaces a Label.

Visual — Do/don't pair (`Doc/Do-dont`):
- Don't: a Text control with placeholder "Email address" and no Label, shown filled with "anna@" so the name is gone.
- Do: the same control with Label "Email address" above it, filled.

## Required and optional

Use the asterisk when most fields in a form are optional. When most are required, leave the asterisk off and mark the few optional ones in the Label text: "Phone (optional)". Explain the asterisk once at the top of a long form ("Fields marked * are required").

Visual — two short forms side by side: one with asterisks on two of five fields, one with "(optional)" on one of five fields. Caption: *Mark the minority.*

## Help icon vs Help text

The help icon is for short, non-essential detail ("Why do we ask for this?"). Anything the user needs to fill the field correctly — format, limits, consequences — goes in Help text under the control, where it is always visible.

Visual — Do/don't pair:
- Don't: Label "Password" with a help icon whose open tooltip reads "8+ characters, one number".
- Do: Label "Password" with Help text "Use 8 or more characters with at least one number."

## Disabled fields

A disabled field keeps its Label at the normal colour so users can still read what it is and why it might be unavailable. The control carries the disabled look.

Visual — a disabled Text control under a rest Label, with a `Doc/Callout` on the Label: "unchanged".

## Placement

Labels sit above the control by default. In wide settings layouts they may sit to the left at a fixed column width, aligned to the control's first text line. Use one placement per form.

Visual — the same three fields in a stacked layout and in a two-column settings layout.

## Content

- Name the information asked for as a short noun phrase: "Email address", "Company name", "Start date".
- Use sentence case and no trailing colon.
- Keep labels to one line at the narrowest field width; move explanation to Help text.
- Don't phrase the label as an instruction ("Enter your email").

## Accessibility

- The Label is programmatically linked to its control, so it becomes the control's accessible name; clicking it moves focus to the control.
- The asterisk is hidden from assistive technology; the control itself carries the required state, so users hear "required" once.
- The asterisk is a glyph, not only a colour, so the required marker does not rely on colour.
- The help icon is a separate focusable trigger in the field (see `Help icon`, 2.13); its tooltip text is the trigger's description, not part of the Label's name.
- Label text meets the text contrast threshold on the surface behind it in every colour mode.

# 11. QA

Fail QA when:
- the Label text, asterisk and help icon are flattened into one text layer or unrelated layers;
- the asterisk is typed into the Label text instead of being the `Asterisk` layer;
- the help icon is a loose icon instead of an instance of `Help icon`;
- opening the help icon's tooltip changes the Label's size or moves the control below it;
- a field in any Component draws its own label instead of instancing `Label`;
- the Label changes colour when its control is disabled;
- a `State`, `Destructive` or `Type` property is added to the Label;
- text styles or colours are raw values instead of `type/body/*` styles and `color/text/*` variables.
