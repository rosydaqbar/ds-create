# 2.6 Avatar

Avatars represent one person, team or organisation with a photo, initials or a placeholder icon, with an optional indicator (online, offline, verified, a company logo, a count). The page holds the everyday `Avatar` and the larger `Profile photo` used on profile and account pages, plus the shared image source that both use.

Groups of avatars, the avatar + name + email label, and the add-person button are compositions of this Part and live on 3.4 Avatar group.

# 2. Avatar

Published set: `Avatar`

Variant name pattern: `Size=md, Type=image`

| Property | Type | Values | Default | What it changes |
| --- | --- | --- | --- | --- |
| `Size` | variant | `2xs, xs, sm, md, lg, xl, 2xl` | `md` | side, initials style, icon size, indicator size |
| `Type` | variant | `image, initials, icon` | `image` | content treatment inside the same frame |
| `Image` | instance swap | `.Main/Avatar image` components | first image | the photo (`Type=image`) |
| `Initials` | text | — | "OR" | `Type=initials` |
| `Show ring` | boolean | — | `false` | ring in the surface colour; separates overlapping avatars and photos from same-coloured backgrounds |
| `Show indicator` | boolean | — | `false` | the overlay mark; its type is chosen on the exposed nested `.Main/Avatar indicator` |

Variant count: 7 sizes × 3 types = **21 variants**, with ring and indicator as booleans.

## 2.1 Avatar anatomy

```text
Avatar
size: size/avatar/{Size} square (Fixed)
radius: radius/full
clip: off (so the indicator can sit on the edge)

├─ Surface                              Fixed, full radius, clip on
│  ├─ Image                             Type=image: .Main/Avatar image instance, Fill, cropped to the circle
│  ├─ Initials                          Type=initials: text, centred
│  └─ Placeholder icon                  Type=icon: user icon, centred
├─ Ring                                 optional (Show ring): inside stroke in the surface colour, same size as Surface
└─ Indicator                            optional (Show indicator): .Main/Avatar indicator, absolute position, bottom-right
```

Rules:
- The root stays square. Image, initials and icon are alternate content treatments inside the same frame, never separate components.
- The indicator is an overlay (absolute position, constraints right and bottom). It never pushes the avatar's intrinsic size.
- Every content layer is centred and clipped by Surface.

## 2.2 Private part: `.Main/Avatar indicator`

| Property | Values |
| --- | --- |
| `Type` | `offline, online, verified, company, count` |
| `Size` | `2xs, xs, sm, md, lg, xl, 2xl` (matches the avatar it sits on) |

```text
.Main/Avatar indicator
├─ offline / online                     dot, size/indicator/{step}, ring in the surface colour
├─ verified                             verified-tick icon in brand colour
├─ company                              a small square logo avatar with a ring
└─ count                                pill with a number, type/body/xs/semibold
```

Indicator visuals scale with the avatar size they are paired with (§4).

## 2.3 Private part: `.Main/Avatar image`

| Property | Values |
| --- | --- |
| `Type` | `square, portrait` |

```text
.Main/Avatar image
├─ Image                                image fill (crop/fill mode: Fill)
└─ Details                              documentation only, outside the image bounds
   ├─ Name                              the image's name
   └─ Source                            where it comes from and its licence
```

One component per image. `Avatar` and `Profile photo` swap between these components through their `Image` property, so replacing the fill inside one component updates every avatar that uses it.

# 5. States

Avatar is not interactive by itself. When it is the trigger of a menu, the wrapping component (an account menu, 3.6 Menu) owns hover and focus: the focus ring sits around the avatar using `focus/default` with `radius/full`.

# 8. Guidelines

`2.6 Avatar · Guidelines` is a dedicated long-form frame. Topics, in order:

## 8.1 Avatar image usage
Explain the image-source strategy and the licensing and source requirements in project terms: where images come from, who may use them, and that demo photos are replaced by real user data in product. Do not name external providers unless the generated system actually uses them. Module §9.6.

## 8.2 Shared avatar images
Explain how avatar images are stored as `.Main/Avatar image` components so one source update propagates to every design that uses them. Module §9.1.

## 8.3 How to change an avatar
The workflow for replacing an avatar image without detaching anything: swap `Image` on the instance to another `.Main/Avatar image` component; or replace the fill inside the part to update everywhere. Include a visual of the replacement. Modules §9.2, §9.3.

## 8.4 How to change placeholder imagery
Explain how the placeholder icon and initials are changed centrally (the placeholder icon is one icon instance; initials are a text property). Module §9.4.

## 8.5 How to change placeholder colours
Explain that placeholder backgrounds and text are token-driven (`avatar/placeholder/*`), so the system updates them globally. Include a placeholder example and a token update example. Module §9.5.

## 8.6 Choosing a size and a type
- Size follows the context: `2xs`/`xs` inside tags, badges and dense tables; `sm`/`md` in lists, comments and top bars; `lg`–`2xl` in cards and headers; `Profile photo` on profile pages.
- Type: image when a photo exists; initials when a name exists; icon when nobody is assigned or the identity is unknown.

## 8.7 Indicators
- Online and offline show presence; verified marks a confirmed identity; company marks the organisation a person belongs to; count shows unread items.
- Indicators always sit bottom-right, overlay the edge and never change the avatar size.
- Presence never relies on colour alone in product: pair it with text in tooltips or lists ("Online").

## 8.8 Accessibility
- Avatars that identify someone have alternative text with the person's name; decorative repeats (the same person next to their name) have empty alternative text.
- Initials meet text contrast on the placeholder fill.
- Indicators have a text equivalent in code.

## 8.9 Do / don't
- Do: initials when there is no photo. Don't: a stock face as a fallback.
- Don't: an indicator that pushes the avatar out of alignment.
- Don't: stretch or squash an image; crop it.
- Don't: detach an avatar to change its photo.

The documentation describes the generated library's actual mechanism.

# 10. QA

Fail QA when:
- indicators push layout instead of overlaying;
- image, initials and icon states are separate unrelated components;
- the root is not square or the radius is not `radius/full`;
- avatars don't swap images through `.Main/Avatar image`, or images are pasted as raw fills per variant;
- placeholder colours are not bound to `avatar/placeholder/*`;
- `Status icon`, `Avatar label group`, `Avatar group` or an add-button set exists on this page (the last three belong to 3.4);
- avatar-management documentation is missing, or described without editor examples;
- source replacement does not demonstrate propagation;
- placeholder changes are not shown with real generated tokens;
- the documentation uses unrelated stock screenshots.
